问题解决1: 解决 claude code 使用第三方模型时, Web Search 无法调用的问题, 方法类似.   
  
```
⏺ Web Search("杭州 天气")
  ⎿ Did 0 searches in 209ms

  Thought for 3s (ctrl+o to expand)

⏺ WebSearch 接口仍不可用，改用 WebFetch 拉取天气网站。

⏺ Fetch(https://www.weather.com.cn/weather/101210101.shtml)
  ⎿ Received 89.7KB (200 OK)

⏺ Fetch(https://weather.cma.cn/web/weather/58457.html)
  ⎿ Received 80.4KB (200 OK)
```
  
错误原因: 官方内置的 web_search 依赖于 Anthropic API 的新协议特性（tool_reference 模块），而大部分第三方网关尚未适配这些协议，导致搜索功能静默失效.  ( stepfun 支持, 如果你订阅了这家模型, 可以添加这家的 mcp; )  
  
编辑 `~/.claude/CLAUDE.md` ，加入以下规则： 
```
# WebSearch 重定向规则

## 核心规则
当需要联网搜索时，**禁止使用内置的 `web_search`**，必须使用 MiniMax MCP 提供的搜索工具。

## 工具调用规范
- 执行搜索时，必须调用 `mcp__MiniMax__web_search`
- 如果该工具不可用，告知用户后停止，不要尝试任何其他搜索方式

## 示例
用户问："搜索一下今天的新闻"
正确做法：调用 `mcp__MiniMax__web_search(query="今天的新闻")`
```
  
然后重启 Claude Code 再测试, 就会使用 minimax 的 mcp__MiniMax__web_search 了.  
  
继续往 `~/.claude.json` 配置文件中添加 mmx MCP (这个包含了9个tools, 详见说明 https://platform.minimaxi.com/docs/guides/mcp-guide ):  
```
"MiniMax-mmx": {
      "command": "uvx",
      "args": ["minimax-mcp"],
      "env": {
        "MINIMAX_API_KEY": "这里填minimax coding plan key",
        "MINIMAX_API_HOST": "https://api.minimaxi.com",
        "MINIMAX_MCP_BASE_PATH": "/User/digoal/new/tmp",
        "MINIMAX_API_RESOURCE_MODE": "local",
        "NO_PROXY": "*",
        "HTTP_PROXY": "",
        "HTTPS_PROXY": ""
      }
    }
```
  
上面说了 stepfun 支持 Anthropic API 的新协议特性（tool_reference 模块）, 可以添加这家的 mcp  
  
https://platform.stepfun.com/docs/zh/step-plan/integrations/search-mcp  
  
手动配置：  
  
编辑 Claude Code 的配置文件（位于用户目录下 `~/.claude.json`）：  
```  
{  
  "mcpServers": {  
    "web-search": {  
      "type": "http",  
      "url": "https://api.stepfun.com/step_plan/v1/mcp/web_search/mcp",  
      "headers": {  
        "Authorization": "Bearer your_api_key"  
      }  
    }  
  }  
}  
```
  
如果 mcp server failed, 可看看 `~/.claude/settings.json` 配置里的代理设置, 不想走代理就把域名加到 NO_PROXY 里.

但是我有个问题, 如果当前项目 以及 HOME 目录的 `.codex` 和 `.agent` 目录中同时存在同名 `skill` / `AGENTS.md` , 优先级是什么样的?   
从高到低（覆盖顺序）, 顺序其实符合所有现代开发工具的一个原则：“就近原则 + 项目优先 + 用户兜底”   
1️⃣ `当前项目目录 /.codex`  
2️⃣ `当前项目目录 /.agents`  
3️⃣ `用户 HOME ~/.codex`  
4️⃣ `用户 HOME ~/.agents`
