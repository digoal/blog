01 · 背景 / 动机

先算一笔账：原始向量区到底有多大

IVF 已经把「全量扫」变成「只扫 nprobe 个桶」，但桶里若存原始 float32，容量与带宽依然很贵。

仅原始向量区 · 不含 id / 倒排表 / 缓存 / 副本
286 GiB
100,000,000 × 768 × 4 B
= 307,200,000,000 B
单位校准：这等于 307.2 GB（十进制），也等于 286.1 GiB（二进制，÷1024³）。原文写作「286 GB」，实际按 GiB 计。
① 内存容量
同样机器放不下更多候选；还有主键、过滤字段、复制与 rerank 用的原向量副本。
② 内存带宽
扫描 list 时要把完整 float 向量搬进 CPU；候选一多，带宽先成为瓶颈。
③ 距离计算
每个候选都要算 d 维真实距离，无法用短整数查表代替。
cost_exact ≈ N × distance_cost(d)
→
cost_ivf ≈ nlist 中心搜索 + nprobe 桶内向量 × distance_cost(d)
→
IVF 减少了候选数，但 list 内仍要读完整 float 向量。
02 · 命名澄清

「ivfflat-pq」是工程口语，不是源码类名

Faiss 里标准类名是 IndexIVFPQ；更准确的结构名是 IVF-PQ，论文里叫 IVFADC。

关键：不存在 IndexIVFFlatPQ 这个类
工程文档把「粗量化器使用 Flat index 的 IVF-PQ」口头叫成 ivfflat-pq。二者不是同一个结构的小参数变化：IVFFlat 存原始 float，IVFPQ 存（默认残差）PQ code。
准确的三个名字
IndexIVFPQ = Faiss 类名 · IVF-PQ = 结构名 · IVFADC = 论文名。
index_factory 写法
IVFx,PQyxb；粗量化器常用 IndexFlatL2(d) —— 这才是「flat」一词的来源。
依据：faiss/IndexIVFPQ.h「Inverted file with Product Quantizer encoding. Each residual vector is encoded as a product quantizer code.」· Faiss wiki「Faiss indexes」· DeepWiki IVF 家族页。
02 · 一句话定义 / 图 1

它是什么：选桶 + 残差短码 + 查表排序

IVF-PQ 是「用 IVF 粗量化器选择少量倒排桶，用 PQ 把桶内向量残差压成短 code，并用查表距离近似排序候选」的 ANN 索引。

图 1 · 粗量化器负责把向量映射到 list；ProductQuantizer 把 x − centroid 的残差编码成短 code。查询侧不把所有 code 解码回浮点再算距离，而是先用 query + 粗中心 + PQ 码本构造距离表，再顺序扫描 list 内的 code。
02 · 术语统一

12 个术语，先对齐再往下讲

标注 ⌁ 的条目已回到 Faiss 上游源码 / 官方 wiki 复核。

nlist
倒排 list 数量 = 粗量化中心数。wiki 经验起点 nlist ≈ C·√N（C≈10） ⌁
nprobe
每次查询探测多少个 list。SearchParametersIVF::nprobe = 1 是源码默认值 ⌁；调大提召回，也增扫描量。
coarse quantizer
粗量化器，常见 IndexFlatL2(d)；把向量映射成 list id，提供粗中心 y_C。
residual
残差 x − y_C。IndexIVFPQ 构造函数里 by_residual = true ⌁
M
PQ 子量化器数量，把 d 维切成 M 段。约束 d % M == 0，否则无法等分子空间。
nbits / ksub
每段编号 bit 数，ksub = 2^nbits。wiki：nbits ∈ {8, 12, 16} ⌁
dsub / code_size
dsub = d / M；code_size = ⌈M·nbits/8⌉ 字节。d=768, M=96, nbits=8 → 96 B。
ADC
Asymmetric Distance Computation：query 保持原始 float，库向量只用 PQ code 表示。
IVFADC
论文里的说法：粗量化器 + 残差 PQ。Faiss wiki 直接把 IndexIVFPQ 标为 IVFADC ⌁
OPQ
先学习一个旋转 / 线性变换，再做 PQ，减少固定维度切块造成的失真。
AQ / RQ / LSQ
加性量化家族：用多个码本向量求和表达原向量或残差，与 PQ 的「子空间拼接」不同。
LUT / precomputed table
query 到码本的距离表；残差 L2 下 term 2 可预计算，代价是 nlist·M·ksub 个 float ⌁
03 · 核心原理 / 第一层

IVF 层：把全量候选变成少量倒排桶

像数据库的倒排索引：coarse centroid id → inverted list → (vector id, encoded code)*

IndexIVF::search() 主路径 ⌁
1  quantizer->search(...) 找最近 nprobe 个粗中心
2  invlists->prefetch_lists() 预取这些 list
3  search_preassigned() 扫描选中的 list
4  get_InvertedListScanner() 由子类决定桶内 code 如何打分
第一层误差来自候选桶选择：nprobe 太小 → 真近邻所在 list 未访问。Faiss wiki 原文：「The failure case appears when the cell of the nearest neighbor of a given query is not selected.」
IVF 本身只决定「扫哪些桶」。桶内存什么、距离怎么算，由 IVFFlat / IVFPQ / IVFSQ / IVFAQ 等子类决定 —— 这正是下一层 PQ 的切入点。
03 · 核心原理 / 第二层

PQ 层：切成 M 个子空间，各自独立量化

核心假设：高维向量切成 M 个低维子向量，每个子空间独立训练一个 k-means 码本；向量不再保存完整 float，只保存 M 个最近 centroid 的编号。

set_derived_values() 派生值 ⌁
dsub = d / M
ksub = 1 << nbits
code_size = ceil(M * nbits / 8)
centroids.size = d * ksub
约束：d % M == 0
源码里的三个动作 ⌁
  • train()：对每个子空间分别跑 Clustering(dsub, ksub, cp)
  • compute_code(s)：把向量映射为短码
  • compute_distance_table()：生成 dis_table(m,j) = ‖x_m − c_(m,j)‖²
ProductQuantizer.h 注释：PQ 支持 L2 与内积，但量化误差偏向 L2。IP / cosine 场景要额外验证召回 ⌁
03 · 效果 / 空间

3072 B → 96 B：但别只算 code

压缩只针对向量 payload，不等于整个索引的压缩比：id、list 结构、码本、预计算表与系统元数据仍然占空间。

完整空间账本

+ N × id_size

+ pq_centroids
+ optional_precomputed_table

⌈M·nbits/8⌉ + 8 B / 条；wiki 的 +8 就是向量 id。
pq_centroids
d × 2^nbits × 4 B。例：768 × 256 × 4 ≈ 0.75 MiB。
precomputed_table ⌁
nlist·M·ksub·4 B。nlist=1024, M=96, ksub=256 → 96 MiB。

03 · 图 3 / 查询

查询：三段距离分解 + 查表扫描

IVFPQScanner 不解码回浮点：对每个候选 code 读 M 个子编号、从距离表取贡献并累加，把近似距离放进 top-k heap。

L2 + 残差 PQ 的距离分解（源码注释原文）⌁
d = ‖x − y_C − y_R‖²
= ‖x − y_C‖²  term 1 · 粗量化阶段已得到
  + ‖y_R‖² + 2⟨y_C, y_R⟩  term 2 · 与 x 无关，可预计算
  − 2⟨x, y_R⟩  term 3 · 经典 PQ 查表项
x = query，y_C = 粗量化中心，y_R = PQ 残差 centroid 组合。扫描时 term 2 与 term 3 的表相加。
预计算表：典型的空间换 CPU
term 2 需要 nlist × M × ksub 个 float，use_precomputed_table = 0 时按启发式决定（上限 2 GiB）。源码注释：list 长度 > ksub × M 时更快。

06 · 优化 / 预处理

OPQ：先旋转，再切块

PQ 固定按维度切块，这个假设在真实 embedding 上未必成立；OPQ 学一个空间变换，让变换后的维度更适合 PQ 切分。

它带来什么
通常能降低 PQ 量化误差；注意它只降低量化误差，无法解决未 probe list 的漏召回 —— 那是 IVF 层的问题。
它要付出什么
训练更贵；索引读写路径多一层变换；跨版本迁移与在线重建都要保存变换矩阵 R。
源码位置：faiss/VectorTransform.h、index_factory.cpp 的 OPQ([0-9]+)(_[0-9]+)? → IndexPreTransform ⌁
06 · 图 4 / 相邻技术

PQ / OPQ / AQ：都是短码，编码模型完全不同

PQ 是子空间拼接，OPQ 是学一个变换后再 PQ，AQ 是多个码本向量相加。训练目标、误差形态、查询代价与实现复杂度都不同。

PQ · 子空间拼接
y ≈ [ c₁ | c₂ | … | c_M ]
OPQ · 变换后拼接
y ≈ R⁻¹ · [ c₁ | … | c_M ]
AQ · 多码本求和
y ≈ c₁ + c₂ + … + c_M
另一条思路：各向异性量化（Guo et al., ICML 2020）——「重构误差最小」不总等于「召回排序最好」
传统量化最小化重构误差；但 MIPS / 最大内积场景里，高内积候选对排序更重要。该工作提出一族 anisotropic quantization loss，对残差中平行于数据点方向的分量给更高惩罚。配合上文 ProductQuantizer.h 的「量化误差偏向 L2」提示：IP 场景必须额外验证 recall@k。

07 · 图 5 / 效果

效果由四类代价共同决定，不要给固定数字

脱离数据集谈性能没有意义。先看四类代价，再把「旋钮」和它们的联动关系记牢。

① 空间
N·code_size + N·id + list_overhead + pq_centroids + precomputed_table
② 召回
两层影响：nprobe 太小 → 候选 list 没覆盖真近邻；M / nbits 太小 → 近似距离排序错。要看 recall@k，不是只看平均延迟。
③ 延迟
coarse search + build LUT + scan codes + heap / filter / rerank。nprobe↑ 扫描与堆维护增加；M↑ 误差降低但查表累加项更多、code 更长。
④ 训练与维护
train() 先训粗量化器再调 train_encoder()；polysemous training 会重排 PQ centroid 顺序；残差 L2 下可能预计算表。
07 · 实操 DEMO

最小 Faiss Python 实验 + recall 验证

简化自官方 tutorial/python/3-IVFPQ.py；用 exact baseline 观察 nprobe 对召回的影响。

import numpy as np
import faiss

d, nt, nb, nq, k = 32, 2000, 5000, 3, 5
rng = np.random.default_rng(20260526)
xt = rng.random((nt, d), dtype=np.float32)
xb = rng.random((nb, d), dtype=np.float32)
xq = rng.random((nq, d), dtype=np.float32)

nlist, M, nbits = 64, 8, 8
quantizer = faiss.IndexFlatL2(d)
index = faiss.IndexIVFPQ(quantizer, d, nlist, M, nbits)

index.train(xt)
index.add(xb)
index.nprobe = 8
D, I = index.search(xq, k)
print(index.is_trained, index.ntotal, index.nprobe)
# exact baseline：验证 nprobe 对 recall 的影响
exact = faiss.IndexFlatL2(d); exact.add(xb)
_, gt = exact.search(xq, k)

for nprobe in [1, 2, 4, 8, 16, 32]:
    index.nprobe = nprobe
    _, got = index.search(xq, k)
    recall = sum(len(set(got[i]) & set(gt[i]))
                 for i in range(nq)) / (nq * k)
    print(nprobe, recall)

生产测试至少包含
  • 业务 embedding 样本（不要用纯随机数据下结论）
  • 真实 top-k 与 recall@k
  • 过滤条件后的最终返回数量
  • rerank 前后的召回变化
  • nprobe / M / nbits / nlist 的延迟与内存曲线
提示：train_encoder_num_vectors() 通常需要 max_points_per_centroid × ksub 量级样本；示例里的 2000 条训练向量在真实配置下偏少，正式实验要用足量样本。
08 · 最佳实践

三个角色，各守一条线

架构师定目标与边界，DBA 治理稳定性，业务开发者正确理解「近似」的语义。

数据库架构师
把它当召回层，不要当精确排序结构
  • 需要精排时，保留原始向量或更高精度副本做 rerank。
  • 先定业务目标：recall@k、P95/P99、内存上限、更新频率，再反推 nlist / nprobe / M / nbits。
  • 大规模多租户优先 segment 化：每段独立训练或周期性重建，避免全局索引被分布漂移拖垮。
  • 过滤条件很强时，单纯 ANN 后过滤容易返回不足；让过滤参与分片 / 分区 / 粗筛，或扩大候选。
DBA / 运维
监控不能只看 QPS
  • 至少看：list size 分布、扫描 code 数、召回抽样、重建耗时、索引文件大小、进程 RSS。
  • 对 nprobe 做灰度，观察召回与 P99 延迟曲线；不要用默认值长期裸跑。
  • 定期抽样对比 exact baseline。分布漂移时平均距离、召回与 list 负载会一起变差。
  • 预计算表是空间换 CPU：nlist·M·ksub·4 要算进容量规划。
业务开发者
理解「近似 top-k」的语义
  • 查询不要只写 LIMIT 10：高价值场景用更大候选集再 rerank。
  • embedding 模型升级 = 数据分布变更，旧 IVF/PQ 训练结果不能默认继续适用。
  • cosine / inner product / L2 要与模型训练目标一致；PQ 误差偏向 L2，IP 场景额外验证。
  • 不要在频繁更新的小表上过早使用 IVF-PQ；小数据 exact scan 更简单、稳定、可解释。
08 · 使用场景

什么时候该用，什么时候别用

先看规模与更新模式，再按瓶颈选型；ANN 的前提是「允许近似」且「能评估召回」。

✓ 适合
  • 千万到十亿级向量召回，内存和带宽是主要瓶颈。
  • 允许 ANN 近似，能用 rerank 修正最终排序。
  • 数据相对稳定，能批量训练和周期性重建。
  • 查询以 top-k 召回为主，而非强事务下的单行实时更新。
  • 可以接受通过 nprobe 调节召回与延迟。
✕ 不适合
  • 必须返回精确 top-k，且不能 rerank。
  • 数据持续高频更新 / 删除，且不能做 segment 合并或后台重建。
  • 过滤条件极强，但过滤无法参与候选生成。
  • 维度不能被 M 整除，或为凑整导致子空间设计很差。
  • 数据量很小，exact scan 已满足延迟。
  • 业务无法建立 recall 评估集，只能凭感觉调参数。
08 · 常见坑 / 排查

七个常见坑，以及召回下降时的分层排查

最容易犯的错是把「IVF 漏召回」和「PQ 排序误差」混在一起调参 —— 那会让结论完全失真。

坑 1  把 IVFPQ 当成 IVFFlat 加了个压缩开关 —— 不是同一个结构的小参数变化。
坑 2  只看 code 压缩比，不算 id 和预计算表；还有 list 结构与运行时开销。
坑 3  训练样本不代表线上分布 → 粗中心与 PQ 码本一起退化。
坑 4  nprobe 默认 1（源码 SearchParametersIVF）；demo 常手动设 5 / 8 / 10，生产不能不测就沿用。
坑 5  维度与 M 不匹配：d % M == 0 是硬约束，768 维用 M=100 不是「更细」而是非法。
坑 6  把 PQ 误差和 IVF 漏召回混在一起 —— 必须分层排查。
坑 7  忽略过滤后的召回：ANN 先给近似候选再做 SQL 过滤，LIMIT 10 可能最终不足 10 条。
09 · 本讲要点 / 延伸

带走这五句话

结构、账本、误差分层、源码默认值、工程定位 —— 以及六个值得继续想的问题。

01
结构是三层：IVF 粗量化选少量倒排桶 + PQ 把桶内残差压成短 code + ADC 查表近似排序。准确名 IndexIVFPQ / IVF-PQ / IVFADC。
02
压缩只针对 payload：3072 B → 96 B 是 32×，但还要算 id（+8 B）、码本、list 结构与预计算表。
03
误差分两层：未 probe 桶的漏召回（IVF）与近似距离排序错（PQ）。排查必须先提 nprobe 再看 M / OPQ。
04
记住源码默认值：by_residual = true、nprobe = 1、use_precomputed_table = 0；硬约束 d % M == 0。
05
它是召回层索引，不是强一致精确排序结构。用 rerank 修正最终排序，用业务数据画 recall@k / P95-P99 / 内存三条曲线。
