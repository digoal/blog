01 / PROBLEM STATEMENT · LATENCY VS TOTAL I/O

把不可预测的前台写等待，换为平滑的后台写出

backend 寻找可替换页面时若撞上脏页，被迫在 SQL 请求路径同步写出；bgwriter 提前清理可复用脏页，但代价是热页可能重复写。

02 / ARCHITECTURE BOUNDARY · ROLES & PARAMETERS

bgwriter 是提前清理的清洁工，不是 checkpoint 执行者

PostgreSQL 9.2 起 bgwriter 不再处理 checkpoint；其 write() 严格遵守 WAL 先写规则，但持久化收口仍归 checkpointer。
