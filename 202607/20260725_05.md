## 这工具到底是干嘛的？

简单说，Understand Anything 是一个 Claude Code 的插件（也支持 Cursor、Copilot、Gemini CLI 等十几个平台），它把你整个项目扫描一遍，然后生成一个**交互式的知识图谱**。

这个图谱里，每个文件、每个函数、每个类都是一个节点，节点之间有连线表示依赖关系、调用关系、继承关系。你可以像逛地图一样缩放、拖拽、点击查看详情。

配了一张图感受一下：

> 知识图谱可视化效果（大概长这样）：左边是代码文件列表，中间是你整个项目的力导向图，右边点开一个节点能看到这个文件/函数是干嘛的、依赖了谁、被谁依赖。

它不是那种"看起来酷但用不上"的玩具。我实际用下来的感受就是——**它解决了接手新项目时最大的痛点：不知道从哪看起。**

## 实操：在 Claude Code CLI 里一步步跑起来

下面我带你完整过一遍安装和使用的流程。前提是你已经装好了 Claude Code CLI。如果还没装，先去 Anthropic 官网装一下，很快。

### 第一步：安装插件

打开终端，进到你的项目目录，然后在 Claude Code 里执行：

```bash
/plugin marketplace add Egonex-AI/Understand-Anything
```

等几秒钟，再执行：

```bash
/plugin install understand-anything
```

装完之后你不需要重启，直接在同一个 session 里就能用。

如果你用的是其他平台比如 Cursor，更方便——直接把项目 clone 下来，Cursor 会自动识别 `.cursor-plugin/plugin.json`，什么都不用装就能用。

### 第二步：扫描项目，生成知识图谱

这是最核心的一步。在 Claude Code 里输入：

```bash
/understand
```

然后你就看着终端里一行一行地滚动吧——它会先扫描你项目里有哪些文件，识别语言和框架，然后用多智能体并行分析每个文件，提取函数、类、导入导出关系，最后聚合成一个知识图谱。

整个过程根据项目大小不同，可能需要几分钟到十几分钟。

**关于 token 消耗的一个大实话**：第一次跑 `/understand` 会分析整个代码库，如果你的项目很大的话，token 消耗确实不少。建议在有订阅的情况下跑。不过好消息是——后续运行默认是**增量更新**，只重新分析你改过的文件，token 消耗就小多了。

我自己的项目跑了大概 5 分钟，生成了 300 多个节点和 800 多条边。数据保存在项目根目录的 `.ua/knowledge-graph.json` 里。

### 第三步：打开数据看板，开始探索

这一步最有意思。在 Claude Code 里输入：

```bash
/understand-dashboard
```

它会启动一个本地 Web 服务，自动在浏览器里打开一个交互式看板。这个看板长这样：

1. **中间是知识图谱**：每个圆点代表一个文件或函数，颜色代表不同的架构层（API 层是蓝色、服务层是紫色、数据层是橙色等）。
2. **可以平移和缩放**：鼠标拖拽移动视角，滚轮缩放。
3. **点击任意节点**：右边侧栏会显示这个节点对应的代码摘要、完整代码、依赖关系。

我第一次打开的时候，说实话有被震撼到——整个项目的结构像地图一样展现在眼前，哪些模块是核心、哪些是边缘、哪些之间耦合严重，一眼就能看出来。

### 第四步：深度使用，几个最实用的命令

熟悉了图谱之后，这几个命令是我日常用得最多的：

**用自然语言问问题：**
```bash
/understand-chat 支付流程是怎么工作的？
```
它会去图里搜索相关节点，然后结合代码上下文回答你。不用猜关键词，直接问就行。

**看改动的波及范围：**
```bash
/understand-diff
```
提交代码之前跑一下，它能告诉你这次改动会影响哪些模块。我靠这个避免了好几次"改了一个变量结果整个模块崩了"的尴尬。

**深入理解某个文件：**
```bash
/understand-explain src/services/payment.ts
```
给你一份这个文件的通俗解读，包括它属于哪一层、被谁调用、调用了谁、设计模式是什么。

**生成新手引导：**
```bash
/understand-onboard
```
这个是为新同事准备的——它会生成一份按依赖顺序排列的架构学习路径，让新人从底层往上学，而不是一头扎进业务代码里被绕晕。

## 几个我觉得很有用的细节

**1. 支持中文输出**

如果你团队用中文沟通，可以在第一次跑 `/understand` 的时候加个参数：

```bash
/understand --language zh
```

生成的节点描述、摘要、看板的 UI 标签全都是中文的。对于国内的团队或者英文不太好的同学来说，非常友好。

而且第一次运行如果不传 `--language`，它会自动检测你对话用的语言。如果是中文，还会跟你确认一下，确认之后就会固定下来。

**2. 图谱可以提交到 Git，全团队共享**

这是我觉得最妙的设计——知识图谱就是一份 JSON 文件，你把它提交到 Git 里，团队其他人 clone 下来之后，**不用装 Claude Code、不用 LLM、不用 API Key**，只需要一行命令就能打开看板：

```bash
npx https://github.com/Egonex-AI/Understand-Anything/releases/latest/download/understand-anything-viewer.tgz .
```

终端会打印一个 URL，浏览器打开就是完整的交互式看板。所有数据都在本地只读加载，不会离开你的机器。

**3. 可以限制扫描范围**

如果你的项目是大型 monorepo，只想分析前端部分：

```bash
/understand src/frontend
```

指定子目录即可，不会扫描整个仓库。

**4. 自动增量更新**

跑一次 `/understand --auto-update`，它会安装一个 post-commit 钩子。以后每次 git commit，它都会自动增量更新图谱。每次提交都带着最新的图谱，PR 评审的时候特别有用。

## 它背后的原理，几句话说明白

你可能好奇，这个工具怎么能自动理解代码的？

它的核心思路就八个字： **静态分析 + 语义理解，各司其职。**

- **Tree-sitter（静态分析）** ：这是一个确定性解析器，把你的源码解析成语法树。它能100%确定地提取出：这个文件 import 了啥、定义了哪些函数和类、函数调用了哪些其他函数、类的继承关系是什么。同样的代码永远产生同样的结果。
- **LLM（语义理解）** ：在 Tree-sitter 提取的结构基础上，LLM 来做它擅长的事——给代码写通俗易懂的摘要、判断这个文件属于哪一层（API？服务？数据？）、发现业务领域的映射关系。

为什么这个分工很重要？

因为没有 LLM 参与的纯静态分析，虽然准确但只能告诉你"A 调用了 B"，不会告诉你"A 是在处理支付回调"。而只有 LLM 没有静态分析，它可能会产生幻觉，说一个不存在的关系。

两者结合，既保证了数据的准确性，又有了语义的丰富性。

扫描阶段会启动最多 5 个 agent 并行分析：

| Agent | 干的事 |
|-------|--------|
| project-scanner | 扫描项目文件，识别语言和框架 |
| file-analyzer | 提取代码结构，生成节点和边 |
| architecture-analyzer | 判断每个文件属于哪一层 |
| tour-builder | 生成学习路径 |
| graph-reviewer | 检查图谱的完整性 |

## 说点大实话：它不是什么？

这篇文章全是实操，我也得说点冷水。

**首先，它不是魔法。** 如果你的代码库质量很差——比如一个文件 5000 行、命名全是 `a1`、`test2`、`handleStuff`——那它生成的摘要质量也会打折扣。LLM 是在现有的代码上做理解的，代码本身烂的话，巧妇难为无米之炊。

**其次，首次扫描确实费 token。** 中型以上项目第一次跑 `/understand` 的 token 消耗是实打实的。建议在订阅周期内跑，或者跑之前心里有个数。

**但话说回来**：花几块钱的 token，换回省下几天甚至一周的"盲读代码"时间，这笔账怎么算都是值的。我个人的经验是，用它摸清一个中大型项目的大致架构，比单纯靠读代码快至少 5-10 倍。

## 总结一句

如果你经常接手别人的代码、或者在新项目里摸索架构，Understand Anything 是一个值得放进工具箱的工具。它不炫技，但确实能解决实际问题。
