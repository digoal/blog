## CodeGraph vs Understand Anything：两个代码知识图谱工具，我该用哪个？

## 背景

> 同一个问题，两个开源项目给出了截然不同的答案。

最近在折腾 AI 编程工具，发现了一个很有意思的现象——有两个开源项目都在做「代码知识图谱」这件事，但思路完全不同。

一个是 **CodeGraph**（`github.com/colbymchenry/codegraph`），一个是 **Understand Anything**（`github.com/Egonex-AI/Understand-Anything`）。

它们都能分析你的代码库、构建关系图、帮 AI 更好地理解代码。但你要是仔细看一眼，会发现这两个项目的**出发点、使用方式、适用场景，几乎是反着来的**。

我花了几天时间把两个项目都装了一遍、跑了一遍、在 Claude Code CLI 里深度体验了一遍。这篇就跟你聊聊我的真实感受，不吹不黑，纯用户视角。

---

## 先说结论：它们解决的不是同一个问题

这是整篇文章最重要的一句话，先放在前面：

- **CodeGraph 的核心诉求**：让 AI 编程助手更快、更便宜、更少翻文件。
- **Understand Anything 的核心诉求**：让**人**能看懂代码库的全貌和架构。

一个是**为 AI 服务的**，一个是**为人服务的**。

这不是我瞎总结的，你往下看就知道了。

---

## 从安装体验开始比

### CodeGraph 安装

装 CodeGraph 有两种方式：

```bash
# 方式一：一行命令（自带 Node 运行时，不需要你装 Node）
curl -fsSL https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.sh | sh

# 方式二：如果你已经有 Node 了
npm i -g @colbymchenry/codegraph
```

装完之后，还要运行一个关键步骤：

```bash
codegraph install
```

这一步会把 CodeGraph 的 MCP 服务器配置写进 Claude Code（以及其他支持的 AI 工具）的配置文件里。说人话就是——**在你的 Claude Code 里注册一个「外挂技能」** 。

然后进到你的项目里：

```bash
cd your-project
codegraph init -i
```

这一步会扫描项目，构建知识图谱索引，存在 `.codegraph/` 目录下的 SQLite 数据库里。

**总共三步**：装 CLI → 注册 MCP → 初始化项目。

### Understand Anything 安装

Understand Anything 的安装就更简单了，因为它走的是 Claude Code 的插件系统：

在 Claude Code 里直接输入：

```bash
/plugin marketplace add Egonex-AI/Understand-Anything
/plugin install understand-anything
```

装完即用，不需要额外注册。

然后扫描项目：

```bash
/understand
```

它会跑一个多智能体流水线，分析完项目后把知识图谱存在 `.ua/knowledge-graph.json` 里。

**总共两步**：装插件 → 跑命令。

### 安装体验对比

| 维度 | CodeGraph | Understand Anything |
|------|-----------|-------------------|
| 安装步骤 | 3 步（CLI + MCP 注册 + 初始化） | 2 步（插件安装 + 扫描） |
| 是否依赖 Node | 可以不依赖（自带运行时） | 不要求（走 Claude Code 环境） |
| 配置复杂度 | 稍高，涉及 MCP 配置 | 极低，装完就用 |
| 第一次上手时间 | 5-10 分钟 | 2-3 分钟 |

**我的感受**：Understand Anything 的安装体验更丝滑，毕竟走插件系统，几乎零配置。CodeGraph 多了一步 `codegraph install`，但好在安装脚本是交互式的，会帮你自动检测和配置，也不费什么事。

## Claude Code CLI 里用起来有什么不同？

这是重点，两个项目在 Claude Code CLI 里的整合方式和使用体验完全不同。

### CodeGraph：MCP 工具，藏在背后

CodeGraph 的核心交互方式是通过 **MCP（Model Context Protocol）工具**。在 Claude Code 里，你看不到 CodeGraph 的界面，它**在后台默默工作**。

当你问 Claude Code 一个关于代码结构的问题时，比如"这个请求是怎么到达数据库的？"，正常情况下 Claude Code 会自己用 grep、glob、Read 去翻文件——这很费 token，也很慢。

但如果装了 CodeGraph，Claude Code 会优先调 CodeGraph 的 MCP 工具来回答：

- `codegraph_explore`——最常用的，一次调用就能返回相关符号的源码+关系图
- `codegraph_search`——按名字搜符号
- `codegraph_callers` / `codegraph_callees`——看谁调了我/我调了谁
- `codegraph_impact`——改一个符号会影响哪些代码
- `codegraph_node`——看一个符号的完整源码

这些工具**返回的内容是源码片段加关系链路**，Claude Code 拿到后直接就能用，不用自己去翻文件了。

实际效果看它的 benchmark 数据（在 7 个真实开源项目上测的）：

| 代码库 | 文件数 | 成本节省 | Token 节省 | 工具调用减少 |
|--------|--------|---------|-----------|------------|
| VS Code | ~10k | 18% | 64% | 81% |
| Django | ~3k | 8% | 60% | 77% |
| Alamofire | ~110 | 40% | 64% | 58% |

**平均：16% 更便宜、47% 更少 token、22% 更快、58% 更少工具调用。**

这个数据说实话挺硬的。而且 CodeGraph 有一个**文件监听器**，你用编辑器改了代码，它两三秒内自动增量更新索引，不需要你手动同步。

**总结 CodeGraph 的 Claude Code 体验**：你几乎感觉不到它的存在，但你的 Claude Code 回答问题更快了、token 花得更少了、翻文件的次数明显少了。

### Understand Anything：斜杠命令，给你看界面

Understand Anything 的交互方式完全不同——它是**通过斜杠命令直接跟你交互的**。

在 Claude Code 里跑完 `/understand` 扫描项目之后，你输入：

```bash
/understand-dashboard
```

它会启动一个本地 Web 服务，自动在浏览器里打开一个**交互式的可视化看板**。你的整个代码库以知识图谱的形式展现在你面前——每个文件、每个函数、每个类都是一个节点，节点之间有连线表示依赖关系。

你可以在看板里：

- **平移和缩放**图谱
- **点击任意节点**查看代码摘要、完整源码、依赖关系
- **按架构层筛选**（API 层蓝色、服务层紫色、数据层橙色）
- **切换角色视图**（初级开发者/项目经理/高级用户，展示的详细程度不一样）

除了看板，还有几个实用的斜杠命令：

```bash
# 用自然语言问代码库的问题
/understand-chat 支付流程是怎么工作的？

# 看改动会影响哪些模块
/understand-diff

# 深入了解某个文件
/understand-explain src/services/payment.ts

# 生成新人学习路径
/understand-onboard
```

**跟 CodeGraph 最大的区别**：Understand Anything 不是帮你「省 token」的，而是帮你「看懂代码」的。

### 一个形象的比喻

- **CodeGraph** 像给 Claude Code 配了个**导航员**——它抄近路、避拥堵，让你更快到达目的地，但你坐在车里看不到路况全貌。
- **Understand Anything** 像给了你一张**卫星地图**——你可以放大缩小、看地形、标兴趣点，但你自己得开车。

## 技术原理的差异

### CodeGraph：纯确定性分析

CodeGraph 只用 Tree-sitter（一个确定性解析器）来分析代码。同样的代码永远产生同样的结果，**没有 LLM 参与图谱构建**。

```
源码 → Tree-sitter 解析 → SQLite 存储 → MCP 工具查询
```

好处是：
- **速度快**：纯本地，不需要调 API
- **成本为零**：没有 token 消耗
- **结果确定**：不会产生幻觉
- **自动同步**：监听文件变化，增量更新
- **100% 本地**：不需要任何 API Key

代价是：
- **只懂结构，不懂语义**：能告诉你"A 调用了 B"，但不知道"A 是在处理支付回调"
- **没有摘要**：不会给代码写通俗易懂的说明

### Understand Anything：Tree-sitter + LLM 混合

Understand Anything 两者都用：

```
源码 → Tree-sitter 提取结构 + LLM 语义理解 → 知识图谱 JSON → 可视化看板
```

具体分工：

- **Tree-sitter 干的事**：提取导入/导出、函数/类定义、调用关系、继承关系。这是确定性的，同样的代码永远同样的结果。
- **LLM 干的事**：给代码写摘要、打标签、判断架构层归属、做业务领域映射、生成学习路径。

好处是：
- **看得懂代码在干什么**，不只是代码的结构
- **能生成人话解释**
- 能发现业务领域和代码的映射关系

代价是：
- **首次扫描费 token**：大项目第一次跑可能消耗不少
- **如果代码质量差**（五千行一个文件、命名全是 a1/test2），LLM 生成的摘要质量也会打折扣
- **图谱不完全是确定性的**：同一份代码两次跑，LLM 的摘要可能略有不同

### 一张表看懂

| 维度 | CodeGraph | Understand Anything |
|------|-----------|-------------------|
| 图谱构建方式 | 纯 Tree-sitter（确定性） | Tree-sitter + LLM（混合） |
| 是否调用 LLM | 否 | 是 |
| 本地运行 | 完全本地 | 扫描阶段需要 LLM API |
| 增量更新 | 文件监听器自动同步 | `--auto-update` 钩子或手动重跑 |
| 输出格式 | MCP 工具返回源码片段 | JSON 知识图谱 + 可视化看板 |
| 支持语言 | 20+ | 不限制（LLM 兜底） |
| 是否开源 | MIT | MIT |

## 框架支持：CodeGraph 明显更细

CodeGraph 在框架支持上做得很深，能识别 14 个 Web 框架的路由：

- Django 的 `path()`、Flask 的 `@app.route()`、FastAPI 的 `@app.get()`
- Express 的 `app.get()`、NestJS 的 `@Controller` + `@Get`
- Spring 的 `@GetMapping`、Gin 的 `r.GET()`
- Rails、Laravel、ASP.NET、Vapor、SvelteKit 等等

这意味着当你在 Claude Code 里问"这个 URL 对应的处理函数是什么？"，CodeGraph 可以直接从路由定义一路追踪到具体的控制器方法。

Understand Anything 在这块没有做专门的框架支持，它依赖 LLM 来理解代码的业务含义，而不是精确追踪路由。

## 适用场景对比

### 什么时候选 CodeGraph？

- **你经常在 Claude Code 里问代码结构问题**——"这个函数被谁调了"、"修改这个会影响什么"
- **你想省 token、省时间**——团队比较大，每天用 Claude Code 很多，token 开销不可忽视
- **你希望 Claude Code 的回复更精准**——不需要 AI 自己去翻文件编译理解
- **你在 CI/CD 里也想用**——CodeGraph 的 CLI 可以 script 化，比如 `codegraph affected` 找到受影响的测试文件
- **你的代码本身质量不错、命名规范**——纯结构分析就能得到很好的结果

### 什么时候选 Understand Anything？

- **你刚接手一个新项目**——想快速看清全局，而不是一个一个函数地问
- **你需要向团队展示架构**——知识图谱可视化看板比文字描述直观得多
- **你想理解代码的业务含义**——不只是"谁调了谁"，而是"这一块是在干嘛"
- **你需要生成新人文档**——`/understand-onboard` 能生成按依赖顺序排列的学习路径
- **你维护的是一个知识库 Wiki 而非代码**——它支持 Karpathy 模式的 LLM Wiki 分析

### 可以一起用吗？

完全可以，而且我试下来效果不错。

我的用法是：

1. **日常写代码时**：装好 CodeGraph，让它在后台跑着。Claude Code 自动用它的 MCP 工具，回答问题更快更省 token。
2. **接手新项目或需要宏观理解时**：跑一下 `/understand` + `/understand-dashboard`，打开看板看全局架构。然后用 `/understand-chat` 深入了解具体模块。
3. **提交代码前**：`/understand-diff` 看影响范围（Understand Anything） + `codegraph affected` 找到受影响测试（CodeGraph），双重保险。

两者并不冲突，反而互补。

## 一些大实话

**CodeGraph 做得好的**：benchmark 数据很实在，7 个真实项目、多轮取中位数，不是那种放个最好成绩就完事的。自动同步的体验也很好，改了代码不用管它，几秒后索引就更新了。

**CodeGraph 的短板**：它的主要价值体现在 Claude Code 的日常使用中，省 token 省时间。但如果你只是想快速了解一个新项目的架构，它没有一个直观的界面给你"看"，所有交互都是通过 Claude Code 的对话完成的。

**Understand Anything 做得好的**：可视化看板是真好看也真好用——把整个项目变成一张可以缩放点击的地图，这种体验在理解新项目时无可替代。引导式学习路径对新人非常友好。

**Understand Anything 的短板**：首次扫描的 token 消耗是实打实的。另外，它的增量更新不像 CodeGraph 那样有文件监听器自动触发，需要靠 post-commit 钩子或手动重跑。

**两者都不是银弹**——如果你的代码库一团糟（一个文件几万行、命名毫无规律、没有任何注释），两个工具的效果都会打折扣。CodeGraph 还能分析结构，但"含义"层面就别指望了；Understand Anything 靠 LLM 勉强能生成一些说明，但输入太差输出也好不到哪去。

## 最后总结

| 对比项 | CodeGraph | Understand Anything |
|--------|-----------|-------------------|
| 一句话定位 | 让 AI 助手更快更省 | 让人看懂代码全貌 |
| 安装方式 | CLI + MCP 注册 | Claude Code 插件 |
| Claude Code 整合 | MCP 工具（透明后台） | 斜杠命令（主动交互） |
| 是否省 token | ✅ 平均省 47% | ❌ 首次扫描费 token |
| 可视化看板 | ❌ 无 | ✅ 交互式知识图谱 |
| 增量更新 | ✅ 文件监听器自动同步 | ✅ 钩子或手动 |
| 框架路由识别 | ✅ 14 个框架 | ❌ 靠 LLM 理解 |
| 代码摘要/说明 | ❌ 只有结构 | ✅ LLM 生成摘要 |
| 新人引导 | ❌ 无 | ✅ 自动生成学习路径 |
| 适合谁 | 重度 Claude Code 用户 | 新项目探索者/架构师 |

如果你问我现在自己在用什么——我两个都装着。

CodeGraph 跑在后台，让我的 Claude Code 日常对话更快更便宜；Understand Anything 在我接手新项目或者需要给团队讲架构的时候打开看板。

它们不是竞品，用在不同的时候罢了。
