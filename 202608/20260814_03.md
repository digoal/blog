## 背景

两个项目代表了当下 AI Coding Agent 框架的两种截然不同的设计哲学：

- Pi (`earendil-works/pi`)：单维护者（badlogic/exe.dev），MIT 协议，极简核心哲学
- DeepSeek Harness (`deepseek-ai/deepseek-harness`)：大厂背景（DeepSeek AI），Cordis 运行时，一切皆插件

---

## 一、开发者维度

### 架构哲学：极简 vs 运行时

| 维度 | Pi | DeepSeek Harness |
|------|----|----|
| 核心哲学 | 核心最小化，一切皆扩展 | 一切皆插件，插件即服务 |
| 运行时依赖 | 无运行时依赖，直接调用 LLM API | Cordis 作为核心运行时 |
| 语言栈 | TypeScript only | TypeScript + （vendor/cordis） |
| 扩展机制 | ExtensionAPI（20+生命周期事件） | Cordis Service Definition + inject 声明 |
| 包数量 | 10 个包（monorepo） | 30+ 个 `@deepseek-ai/dsh-*` 包 |

Pi 的极简哲学体现在一个核心原则："If your feature does not belong in the core, it should be an extension." 核心仅负责会话管理、消息路由、工具编排。ExtensionAPI 是唯一扩展点，20+ 个生命周期事件覆盖全链路。内置工具（read/write/edit/bash）和用户扩展没有架构差异——这是一个真正扁平的插件系统。

DSH 的插件哲学更深一层：插件本质是 Cordis Service，依赖通过 `inject` 字段声明，Cordis 根据依赖图自动排序激活时机。这实现了声明式组合，而不是手动排序。代价是学习曲线更陡——需要理解 Cordis 的五核心概念（Plugin=Service, Context=Service Repository, inject, Typed Events, Registrations）。

### 代码规模与可审计性

| 指标 | Pi | DeepSeek Harness |
|------|----|----|
| 源码文件 | 1,182 | 3,839 |
| AST 节点 | 19,086 | 40,300 |
| 依赖边 | 83,819 | 226,215 |
| codegraph 建图时间 | 2.7s | 6.9s |

DSH 代码规模是 Pi 的 3 倍，但两者的复杂度来源不同：Pi 的复杂度来自 TypeScript 动态特性和多 Provider 适配；DSH 的复杂度来自插件系统的静态类型约束。

### 供应链安全

Pi 在这方面的工程实践远超 DSH：
- `package-lock.json` 锁定所有传递依赖
- `.npmrc` 设置 `save-exact=true` 和 `min-release-age=2`
- shrinkwrap 生成显式允许清单防止恶意 lifecycle script
- CI 每日 `npm audit` + `npm audit signatures`
- pre-commit 守卫阻止意外 lockfile 提交

DSH 无同等披露。MIT 协议 + 快速迭代阶段意味着安全投入存在但未文档化。

## 二、用户维度

### 安装与门槛

| 维度 | Pi | DeepSeek Harness |
|------|----|----|
| 安装 | `npm install -g @earendil-works/pi-coding-agent` | `npx @deepseek-ai/dsh web` |
| 依赖 | Node.js >= 22 | Node.js ^22.19 或 >= 24 |
| 运行模式 | CLI + TUI（本地终端） | Web UI（:3080）+ CLI |
| 上手难度 | 低（直接交互） | 中（需要浏览器） |

Pi 安装后直接可用，TUI 提供差分渲染（只有变化的部分重绘）和 LaTeX 数学公式渲染。DSH 默认启动 Web UI，第一次需要打开浏览器。

### 权限与安全

这是两个项目最显著的差异：

Pi 的诚实承认：无内置沙箱，设计文档明确说"Pi does not include a built-in permission system"。然后提供三条容器化路径：
1. Gondolin extension：主机保留 pi 和认证，工具命令路由进本地 Linux micro-VM（最实用）
2. Plain Docker：整进程容器隔离（最简单）
3. OpenShell：策略控制沙箱（最严格）

DSH 的 guard 包：提供了 `loop-hygiene`（防止循环）和 `tool-timeout`（工具超时控制），但这是运行时保护而非权限边界。fs capability 有 policy 系统，但安全模型尚未成熟。

### 功能完整性

| 功能 | Pi | DSH |
|------|----|-----|
| 多 Provider 支持 | ✅ OpenAI/Anthropic/Google/自定义 | ✅ DeepSeek 为主 + OpenAI 兼容 |
| 持久化会话 | ✅ SQLite | ✅ 多种 backend |
| 终端 UI | ✅ 差分渲染 TUI | ❌ Web only（暂无 TUI） |
| 技能/Skill 市场 | ❌ | ✅ dsh-skill 包 + 社区 catalog |
| 工具超时控制 | ❌ | ✅ guard plugin |
| 会话共享/HF | ✅ pi-share-hf → HuggingFace | ❌ |

## 三、商业维度

### 团队与可持续性

| 维度 | Pi | DeepSeek Harness |
|------|----|----|
| 背景 | 个人维护者（badlogic/exe.dev） | DeepSeek AI（大厂） |
| 资金来源 | 不明（可能是副业） | DeepSeek 商业公司支撑 |
| 维护频率 | 活跃（有明确节奏） | Developer Preview，快速迭代 |
| 风险 | 单点维护者离职/停止 | 公司战略调整 |
| 企业特性 | 无（SSO/审计需自实现） | 暂无（快速迭代期） |

Pi 的单维护者模式是最大风险，也是最大优势：没有企业政治的代码方向之争，决策快，但可持续性依赖个人投入。exe.dev 的商业模式尚不明确——Pi 本身是 MIT 的，但维护者可能通过企业支持/咨询变现。

DSH 背靠 DeepSeek AI，资源优势明显，但"Developer Preview"阶段意味着接口不稳定，企业生产使用存在升级风险。DeepSeek 的商业逻辑是通过开源 Agent 框架推广其 LLM API（DeepSeek Chat/Reasoner），框架本身不是盈利产品。

### 开源协议

| 维度 | Pi | DSH |
|------|----|-----|
| 协议 | MIT | MIT |
| 限制 | 无 | 无 |
| 商用 | 自由 | 自由 |
| 商标使用 | 未明确 | 未明确 |

两者都是最宽松的 MIT，无专利授权条款。DSH 的"YCDSLP"（Y DeepSeek Software License Product）尚未出现在当前仓库——当前是 MIT。

## 四、生态维度

### 社区与分发

| 维度 | Pi | DeepSeek Harness |
|------|----|----|
| 官网 | pi.dev | 仅有 GitHub + Discord |
| Discord | ✅ | ✅ |
| npm 包 | 5 个 `@earendil-works/pi-*` | 30+ `@deepseek-ai/dsh-*` |
| GitHub Stars | 不详（需网络查询） | 不详（需网络查询） |
| 插件生态 | 早期（手动加载） | 有 topic + catalog 机制 |

DSH 有 `dsh-plugin` GitHub topic + 官方插件目录，生态机制更完整。Pi 的分发通过 npm/git，用户基数可能不小但未公开指标。

### 关联项目

Pi 生态：
- `pi-chat`：姐妹项目，通过 RPC 驱动 Pi 自动化工作流
- `pi-share-hf`：倡导开源社区共享真实编码会话到 HuggingFace，而非闭源基准
- `badlogic/pi-mono`：作者本人的工作会话数据集

DSH 生态：
- Cordis 社区（cordiverse）：独立维护的运行时框架
- E2B 集成：沙箱执行集成
- 已有 `dsh-plugin` topic 的社区插件

### 定位对比

| 竞品 | Pi | DSH |
|------|----|-----|
| Claude Code | 定位相似（本地 CLI） | 定位不同（Web/插件） |
| OpenCode (Codium) | 无 TUI，Web 优先 | 更重 Web UI |
| Cursor/Windsurf | 闭源，编辑器集成 | 开源，可自托管 |
| Github Copilot | 云端， IDE 集成 | 本地优先 |

核心定位差异：Pi 是"开发者的第二双手"，强调本地、透明、可审计；DSH 是"企业 Agent 平台"，强调可组合性、插件生态、大厂背书。

## 五、核心洞察与判断

### Pi 的本质

Pi 是一个工程诚信项目。badlogic 在 AGENTS.md 中写"Technical prose only, be direct"，在 README 中坦诚承认"无内置权限系统，需要容器化"。供应链安全的极致投入说明这是一个认真对待代码质量的个人项目。

它的局限也是明显的：单维护者、没有 Skill 市场、没有 Web UI。单维护者模式在商业化之前是可持续的，但如果维护者转向付费工作（如企业咨询），项目可能陷入维护状态。

### DSH 的本质

DSH 是一个平台赌注。DeepSeek 通过开源 Agent 框架吸引开发者围绕其 LLM API 构建工具链——框架免费，API 收费（Cordis 是手段，DeepSeek Chat 是目的）。Cordis 的声明式组合模型在理论上支持真正的多供应商切换，但在实践中 DSH 主要推广 DeepSeek 模型。

Developer Preview + breaking changes 是合理阶段选择，但也是企业用户的主要顾虑。

### 如果必须选择

选 Pi 的理由：你想理解代码在做什么、你想透明控制 Agent 行为、你需要供应链安全（商用）、你喜欢终端开发体验。

选 DSH 的理由：你想构建插件产品、你需要多供应商灵活切换、你在构建企业级 Agent 平台、你愿意跟随快速迭代承受接口变化。

### 一个深层矛盾

两个项目都在解决同一个问题：如何让 Agent 可靠地执行复杂任务，但它们的哲学截然相反：

- Pi 认为 Agent 应该小而透明，人类始终是最终决策者
- DSH 认为 Agent 应该是可组合的服务，人类是配置者而非操作者

这不是功能差异，而是价值观差异——关于 AI 应该扮演什么角色的根本分歧。
