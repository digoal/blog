## 建议将外置移动 SSD 硬盘格式化为 apfs  
以三星 T7 SSD 移动硬盘为例  
  
```  
# 0. 查看设备号  
$ diskutil list  
  
/dev/disk4 (synthesized):  
   #:                       TYPE NAME                    SIZE       IDENTIFIER  
   0:      APFS Container Scheme -                      +1000.0 GB  disk4  
                                 Physical Store disk6s2  
   1:                APFS Volume T7                      85.5 GB    disk4s1  
  
/dev/disk6 (external, physical):  
   #:                       TYPE NAME                    SIZE       IDENTIFIER  
   0:      GUID_partition_scheme                        *1.0 TB     disk6  
   1:                        EFI EFI                     209.7 MB   disk6s1  
   2:                 Apple_APFS Container disk4         1000.0 GB  disk6s2  
  
  
# 1. 卸载(注意你要操作的是 external, physical : disk6)  
sudo diskutil unmountDisk /dev/disk6  
  
# 2. 重新分区格式化  
sudo diskutil partitionDisk /dev/disk6 1 GPT APFS "T7" 0  
  
# 3. 验证  
diskutil list disk6  
  
# 4. 查看  
$ mount  
  
/dev/disk4s1 on /Volumes/T7 (apfs, local, nodev, nosuid, journaled, noowners)  
```  
  
## 加入搜索黑名单  
防止 macOS 的搜索给这块盘建立索引(会消耗资源), 可以直接关掉(拉黑).  
  
命令行操作  
```  
# 确认当前状态  
sudo mdutil -s /Volumes/T7  
  
# 如果不是 disabled，执行禁用  
sudo mdutil -i off /Volumes/T7  
```  
  
或图形界面, 打开设置-聚焦-搜索隐私-将 `/Volumes/T7` 添加到隐私(防止聚焦搜索这些位置)中  
  
## 减少写 IO, 提高 SSD 寿命
mount 看到 :   
```
/dev/disk4s1 on /Volumes/T7 (apfs, local, nodev, nosuid, journaled, noowners)
```  
  
加 `noatime` 选项 , 避免每次读操作修改最后一次访问时间(文件元数据)  
  
可以减少写 IO , 提高 SSD 寿命  
  
被弹出后, 都需要重新 mount 重载, 例如  
```
# 加 noatime 不需 umount
sudo mount -u -o noatime,nodev,nosuid,noowners /Volumes/T7
```
  
  
## 将 macOS Docker 镜像、容器、容器外挂 Volume 都放到外置移动 SSD 硬盘  
  
1、先停掉所有容器, 然后退出 docker desktop app.  
```  
# 停容器内的服务, 以 hermes profile digoal gateway 为例子  
docker ps  
docker exec -ti pg bash  
digoal gateway stop  
  
# 停掉所有容器例如  
docker ps  
docker stop pg  
  
# 然后退出 docker desktop app.  
```  
  
2、拷贝, 建议使用 ditto  
  
在外置移动 SSD 硬盘创建目录  
```  
cd /Volumes/T7  
mkdir macmini_m2_docker_data  
```  
  
拷贝 pg 容器外挂 Volume 和存放镜像、容器的虚拟盘文件  
```  
sudo ditto -V --nocache ~/pgdocker_data_test /Volumes/T7/macmini_m2_docker_data/pgdocker_data_test  
  
sudo ditto -V --nocache ~/Library/Containers/com.docker.docker/Data/vms/0/data /Volumes/T7/macmini_m2_docker_data/docker_resource_data  
```  
  
3、创建软链接  
  
确认拷贝成功后, 删除已有文件  
```  
rm -rf ~/pgdocker_data_test  
  
rm -rf ~/Library/Containers/com.docker.docker/Data/vms/0/data  
```  
  
创建软链接  
```  
ln -s /Volumes/T7/macmini_m2_docker_data/pgdocker_data_test ~/pgdocker_data_test  
  
ln -s /Volumes/T7/macmini_m2_docker_data/docker_resource_data ~/Library/Containers/com.docker.docker/Data/vms/0/data  
```  
  
4、启动 docker desktop, 启动容器, 进入看看容器内服务是否正常  
```  
# 启动 docker desktop app  
  
# 启动容器  
docker start pg  
  
# 进入容器  
docker exec -ti pg bash  
  
# 启动 hermes gateway  
digoal_gateway  
```  
  
## 长期使用后, 给 SSD 做 TRIM, 提高性能  
  
如果你的 SSD (外置、内置 SSD 都可以用)格式化是 APFS 格式, 可以参考如下, 提高性能.  
  
`sudo fsck_apfs -T` 是 macOS 下给 APFS 格式的 SSD 做 “深度垃圾回收” 的最佳命令。它能在不删除数据的前提下，有效恢复因长期写入导致的性能下降，是维护外置 SSD（如你的 T7）最推荐的方式。  
  
这条命令的好处，可以总结为给 SSD 做一次“深度SPA”。  
  
它不是简单的“删除垃圾”，而是强制触发 SSD 内部最核心的垃圾回收（GC）机制，以此恢复性能。  
  
具体好处是：  
  
1、恢复“脏盘”性能：SSD 在写入数据前，必须先把目标块擦干净。如果主控提前在后台（通过TRIM）完成了擦除，你下次写入时就能达到理论满速。如果没有`TRIM`，写入操作会变成“读-改-写-擦”的四步流程，速度会严重下降。这也是为什么你拷贝海量小文件后速度会掉到1MB/s的原因之一。  
  
2、减少写入放大，延长寿命：提前擦除能让主控用更高效的方式整理数据，减少不必要的“搬运”操作，从而减少对闪存颗粒的实际写入量，延长硬盘寿命。  
  
3、在不格式化的情况下“清理”磁盘：这和你之前通过重新分区（`partitionDisk`）来恢复性能的方式不同。`fsck_apfs -T` 不会删除任何数据，只是让主控回收“已删除文件”留下的空间，是日常维护的最佳选择。  
  
首先, 停掉容器, 退出docker desktop app, 不再赘述.  
  
然后要卸载卷  
```  
# 查看卷名  
mount  
  
/dev/disk4s1 on /Volumes/T7 (apfs, local, nodev, nosuid, journaled, noowners)  
  
# 与重建分区不同, 清理要对磁盘容器进行操作 也就是 APFS Container Scheme  
diskutil list  
  
/dev/disk4 (synthesized):  
   #:                       TYPE NAME                    SIZE       IDENTIFIER  
   0:      APFS Container Scheme -                      +1000.0 GB  disk4  
                                 Physical Store disk6s2  
   1:                APFS Volume T7                      33.4 GB    disk4s1  
  
/dev/disk6 (external, physical):  
   #:                       TYPE NAME                    SIZE       IDENTIFIER  
   0:      GUID_partition_scheme                        *1.0 TB     disk6  
   1:                        EFI EFI                     209.7 MB   disk6s1  
   2:                 Apple_APFS Container disk4         1000.0 GB  disk6s2  
```  
  
`sudo fsck_apfs -T` 应该作用于 APFS 容器，也就是 disk4，而不是物理盘 disk6。  
  
对 disk4（逻辑容器） 执行 TRIM。  
  
不要对 disk6（物理盘，会导致命令报错） 执行。  
  
不需要对 disk6s2 执行（它只是容器的存储空间，操作它等同于操作 disk4，但直接操作容器更标准）。  
  
具体操作如下:  
```  
# 再次提醒 首先, 停掉容器, 退出docker desktop app, 不再赘述.  
  
# 1. 卸载容器（必须先卸载）  
sudo diskutil unmount /dev/disk4s1  
  
# 2. 对容器执行 TRIM（注意：目标不是 disk6，而是 disk4）  
sudo fsck_apfs -T /dev/disk4  
  
# 3. 重新挂载卷（因为容器卸载后卷也被卸载了）  
sudo diskutil mount /dev/disk4s1  
```
