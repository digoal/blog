## 背景  

把我的“屠龙刀”搬进 SSD 移动硬盘后, 不知道是移动硬盘问题还是碰巧, 使用一段时间后, 出现了Hermes SQLite 数据文件损坏问提. 
  
通用方法无法修复
```
digoal doctor --fix
hermes doctor --fix 
```
  
使用 `.recover` 命令（最简单，推荐首选）
```
# 1. 使用 SQLite 内置恢复工具
sqlite3 ~/.hermes/profiles/digoal/state.db ".recover" > ~/state.db.sql

# 2. 将恢复的数据导入新数据库
sqlite3 ~/state.db.recovered < ~/state.db.sql

# 3. 检查数据是否完整
sqlite3 ~/state.db.recovered "SELECT COUNT(*) FROM messages;"
sqlite3 ~/state.db.recovered "SELECT COUNT(*) FROM sessions;"

# 4. 如果数据完整，重建 FTS 索引
sqlite3 ~/state.db.recovered <<EOF
CREATE VIRTUAL TABLE messages_fts_new USING fts5(content, tokenize='porter unicode61');
INSERT INTO messages_fts_new(rowid, content) SELECT id, content FROM messages;

CREATE VIRTUAL TABLE messages_fts_trigram_new USING fts5(content, tokenize='trigram');
INSERT INTO messages_fts_trigram_new(rowid, content) SELECT id, content FROM messages;

DROP TABLE IF EXISTS messages_fts;
DROP TABLE IF EXISTS messages_fts_trigram;
ALTER TABLE messages_fts_new RENAME TO messages_fts;
ALTER TABLE messages_fts_trigram_new RENAME TO messages_fts_trigram;

VACUUM;
PRAGMA integrity_check;
EOF

# 5. 替换原文件（先备份）
cp ~/.hermes/profiles/digoal/state.db ~/.hermes/profiles/digoal/state.db.backup
mv ~/state.db.recovered ~/.hermes/profiles/digoal/state.db
```
  
验证修复
```
# 1. 检查完整性
sqlite3 ~/.hermes/profiles/digoal/state.db "PRAGMA integrity_check;"

# 2. 检查 FTS 功能
sqlite3 ~/.hermes/profiles/digoal/state.db "SELECT COUNT(*) FROM messages_fts;"
sqlite3 ~/.hermes/profiles/digoal/state.db "SELECT rowid FROM messages_fts WHERE content MATCH 'test' LIMIT 1;"

# 3. 测试 Hermes 是否正常
hermes list  # 或你的启动命令

# 4. 删除备份
rm -f ~/.hermes/profiles/digoal/state.db.backup
```
