## 背景 
我给 Hermes Agent 写了 20 几行的 SOUL.md, 使用时发现并不是全量进入 context, 而是会选出若干意图相关的表述(甚至都不是整行、也不是原始的表述)进入 context.

例如, 我说: "写文章解释这个现象"

第一步得到的是来三个部分组合的内容: `SOUL.md` + `memory` + 我说的
```
按 SOUL "画龙点睛不是画蛇添足" + "对数据敏感" + "第一性原理" + memory "先搜证，再追问为什么" + "犀利观点 + 适用边界 + 前提假设"+ 主人"写文章解释这个现象" — 写一篇带主人范式的文章(不是 introspections 的 -hot 版，是给主人看的):
```

SOUL.md 不是每次交互都全部自动注入。
  
澄清几个层面:
  
1\. SOUL.md 是 profile 级静态文件, 只在特定时机被读
- 路径: `~/.hermes/profiles/digoal/SOUL.md` (或由 `paths.soul_file` 配置指定)
- 不是 `message-level` 自动注入, 而是 `agent` 在需要时主动 `read_file` 加载
- 你说的 "每次都注入" —— 实际上不是真的"每次",而是:
    - `agent` 启动时按需加载
    - 部分场景下被 `plugin/hook` 自动 `cat` 进 `system prompt`
    - 关键判断: 它是人格/价值观基线,不是每轮对话都重读的
  
2\. 真正的"每次注入"是这三块(区分清楚)

| 注入项                        | 何时注入                | 频率                |
|-------------------------------|-------------------------|---------------------|
| MEMORY.md / USER.md           | system prompt 顶层      | 每次会话(全文,静态) |
| PowerContext prepared context (这是我配置的 memory provider, 你的可能不是哦) | PowerContext 工具调用后 | 每次 recall,动态    |
| SOUL.md                       | 取决于 plugin 配置      | 不一定每轮          |
  
3\. 你这次问的潜在意图我猜是: 想确认"主人给我设置的人格设定是不是每次都生效" —— 答案是通过 system prompt 顶层的 MEMORY/USER 静态注入 + PowerContext 动态 recall, SOUL.md 是补充基线, 三者协同保证跨会话的人格一致性。
