# 安装 cuda 驱动  
debian 13 官方的版本太低, ollama 要求 570+, debian 13 是 550+, 而我的 mx150 显卡只能用到 580, 再高 cuda 已经放弃对 mx150 的支持.  
  
1、禁用自带的 nouveau 模块, 我们要用独显  
  
```  
root@digoal-home:~/new/download# cat /etc/modprobe.d/blacklist-nouveau.conf  
blacklist nouveau  
blacklist lbm-nouveau  
#blacklist nvidia  
#blacklist nvidia_drm  
#blacklist nvidia_modeset  
#blacklist nvidia_uvm  
options nouveau modeset=0  
```  
  
```  
root@digoal-home:~/new/download# cat /etc/modprobe.d/nvidia.conf  
# You need to run "update-initramfs -u" after editing this file.  
  
# Nouveau/Nova must be blacklisted here as well beside from the initrd to avoid  
# a delayed loading (for example on Optimus laptops where the Nvidia card is not  
# driving the main display).  
  
blacklist nouveau  
blacklist nova-core  
  
# Enable complete power management. From:  
# file:///usr/share/doc/nvidia-driver/html/powermanagement.html  
  
options nvidia NVreg_TemporaryFilePath=/var/tmp  
options nvidia NVreg_EnableS0ixPowerManagement=1  
options nvidia NVreg_PreserveVideoMemoryAllocations=1  
```  
  
更新 ramfs 重启  
  
```  
sudo update-initramfs -u  
sudo reboot  
```

# 安装 ollama  
  
  
https://docs.ollama.com/linux  
  
  
1、Manual install  
  
If you are upgrading from a prior version, you should remove the old libraries with `sudo rm -rf /usr/lib/ollama` first.  
  
Download and extract the package:  
```  
curl -fsSL https://ollama.com/download/ollama-linux-amd64.tar.zst -o ./ollama-linux-amd64.tar.zst  
```  
  
安装  
```  
sudo tar --zstd -xvf ollama-linux-amd64.tar.zst -C /usr  
```  
  
注意看安装输出, 给 AI 帮你写 ollama systemctl service  
  
```  
ollama --version  
  
ls -la /usr/lib/ollama/llama-server  
```  
  
  
2、测试  
  
```  
LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu:/usr/local/lib/ollama/cuda_v12:$LD_LIBRARY_PATH \
OLLAMA_HOST=0.0.0.0:11434 \
OLLAMA_NUM_PARALLEL=1 \
ollama serve  
```  
  
如果遇到 llama-server 找不到的日志, 可能需要手工软链接, 正常情况不需要  
  
```  
# find / -name "llama-server"  
/usr/lib/ollama/llama-server  
  
sudo ln -s /找到的路径/llama-server /usr/local/lib/ollama/llama-server 软链到报错日志中提到的位置  
```  
  
  
3、配置 ollama systemctl 服务, 让它随服务器启动  
```  
sudo systemctl edit --force --full ollama.service  
```  
  
输入  
```  
[Unit]  
Description=Ollama Service  
After=network-online.target  
  
[Service]  
Type=simple  
User=root  
Group=root  
ExecStart=/usr/local/bin/ollama serve  
Restart=always  
RestartSec=3  
Environment="OLLAMA_HOST=0.0.0.0:11434"  
Environment="OLLAMA_KEEP_ALIVE=2m"  
Environment="OLLAMA_NUM_PARALLEL=1"  
Environment="OLLAMA_MAX_LOADED_MODELS=1"  
Environment="OLLAMA_LOAD_TIMEOUT=10m"  
Environment="OLLAMA_FLASH_ATTENTION=1"  
Environment="LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu:/usr/local/lib/ollama/cuda_v12"  
  
[Install]  
WantedBy=default.target  
```  
  
  
  
  
重载 systemd  
```  
sudo systemctl daemon-reload  
```  
  
启用服务（开机自启）  
```  
sudo systemctl enable ollama.service  
```  
  
启动服务  
```  
sudo systemctl start ollama.service  
```  
  
查看服务状态  
```  
sudo systemctl status ollama.service  
```  
  
查看服务配置  
```  
systemctl cat ollama  
```  
  
查看服务日志  
```  
sudo journalctl -u ollama.service -n 20 --no-pager  
```  
  
  
测试 Ollama API  
```  
curl http://localhost:11434/api/tags  
```

6、修改 ollama systemctl 服务配置  
  
  
```  
mkdir -p /etc/systemd/system/ollama.service.d  
  
  
sudo tee /etc/systemd/system/ollama.service.d/override.conf << 'EOF'
[Service]  
# ============================================  
# 1. 网络与访问控制  
# ============================================  
  
# 监听所有网络接口，允许外部访问  
Environment="OLLAMA_HOST=0.0.0.0:11434"  
  
  
# ============================================  
# 2. 模型加载与内存管理  
# ============================================  
  
# 模型常驻内存（-1 表示永不卸载，直到服务停止）  
Environment="OLLAMA_KEEP_ALIVE=-1"  
  
# 最大并行处理的推理请求（MX150 显存小，建议 1）  
Environment="OLLAMA_NUM_PARALLEL=1"  
  
# 最多同时加载几个模型到内存（显存 2.2GB，建议 1-2）  
Environment="OLLAMA_MAX_LOADED_MODELS=2"  
  
# 模型加载超时时间（大模型加载慢，10 分钟足够）  
Environment="OLLAMA_LOAD_TIMEOUT=10m"  
  
# 启用 Flash Attention（减少显存占用，加速推理）  
Environment="OLLAMA_FLASH_ATTENTION=1"  
  
  
# ============================================  
# 3. cuda GPU 加速配置  
# ============================================  
  
# 强制 Ollama 仅使用 CUDA , 但如果 cuda 没有正确识别, 会导致回退到纯 cpu, 所以一定要确认  
# 重启后确认 是否启用 cuda: sudo journalctl -u ollama | grep -E "(CUDA|cuda|inference)" | tail -10  
# Environment="OLLAMA_VULKAN=0"  
  
# 强制使用 CUDA 后端（NVIDIA GPU 优化更好）  
# Environment="OLLAMA_GPU_BACKEND=cuda"  
  
# 指定使用哪块 GPU（0 是第一块）  
# 这个只管英伟达 cpu, 集成显卡不占编号
# Environment="CUDA_VISIBLE_DEVICES=0"  
  
# CUDA 库路径  
# Environment="LD_LIBRARY_PATH=/usr/lib/ollama/cuda_v12:/usr/lib/x86_64-linux-gnu"  
  
  
# ============================================  
# 3. vulkan GPU 加速配置 和 cuda 二选一 , 实测哪个快就选哪个  
# ============================================  
  
Environment="CUDA_VISIBLE_DEVICES="  
Environment="OLLAMA_GPU_BACKEND=vulkan"  
Environment="OLLAMA_VULKAN=1"  
# 强制 Vulkan 仅使用第 2 块 GPU，即 MX150, 后面有提到
# vulkan-tools 包 vulkaninfo 命令查看编号
Environment="GGML_VK_VISIBLE_DEVICES=1"
  
  
# ============================================  
# 4. 代理配置（API 走代理，下载直连）  
# ============================================  
  
# 大写环境变量（兼容某些应用）  
Environment="HTTP_PROXY=http://127.0.0.1:22222"  
Environment="HTTPS_PROXY=http://127.0.0.1:22222"  
Environment="ALL_PROXY=http://127.0.0.1:22222"  
  
# 小写环境变量（Go 应用优先读取）  
Environment="http_proxy=http://127.0.0.1:22222"  
Environment="https_proxy=http://127.0.0.1:22222"  
Environment="all_proxy=http://127.0.0.1:22222"  
  
# 不走代理的域名（模型下载直连，加速）  
Environment="NO_PROXY=.r2.cloudflarestorage.com,.docker.io,.registry.ollama.ai,.edu.cn,.nvidia.cn,.nvidia.com,.aliyun.com,localhost,127.0.0.1,.playwright.dev,.npmmirror.com,.minimaxi.com,.stepfun.com,.deepwiki.com,.weixin.com,.qq.com,host.docker.internal,.gh-proxy.com,.tsinghua.edu.cn"  
Environment="no_proxy=.r2.cloudflarestorage.com,.docker.io,.registry.ollama.ai,.edu.cn,.nvidia.cn,.nvidia.com,.aliyun.com,localhost,127.0.0.1,.playwright.dev,.npmmirror.com,.minimaxi.com,.stepfun.com,.deepwiki.com,.weixin.com,.qq.com,host.docker.internal,.gh-proxy.com,.tsinghua.edu.cn"

# Environment="OLLAMA_MODEL_REFRESH_INTERVAL=300"  
  
EOF
  
  
# reload 并重启服务  
sudo systemctl daemon-reload  
sudo systemctl restart ollama  
```

```
# 安装 vulkaninfo
apt update
sudo apt install vulkan-tools

# 安装后查看设备
root@digoal-home:~# vulkaninfo --summary 2>/dev/null | grep -E "deviceName|deviceID"
	deviceID           = 0x5917
	deviceName         = Intel(R) UHD Graphics 620 (KBL GT2)
	deviceID           = 0x1d10
	deviceName         = NVIDIA GeForce MX150
	deviceID           = 0x0000
	deviceName         = llvmpipe (LLVM 19.1.7, 256 bits)
```
   
设备列表解读   
  
Vulkan 识别了三个设备，按顺序排列：  
  
设备 0：Intel UHD Graphics 620（集成显卡）  
  
设备 1：NVIDIA GeForce MX150（独立显卡）  
  
设备 2：llvmpipe（纯软件渲染器，是 LLVM 的软件备选方案，性能极低，一般仅作备用）  
  
  
ollama systemctl service `GGML_VK_VISIBLE_DEVICES=1` 这个设置，告诉 Ollama 的 Vulkan 后端：“跳过 0 号和 2 号设备，只使用 1 号设备”，从而完美锁定 MX150 独显。

# 监控 nvidia 卡的使用  
  
1、检查 CUDA 是否真的在用  
  
```  
# 查看 Ollama 使用的 GPU 后端  
ollama ps  
```  
  
  
```  
# 查看 CUDA 版本的 llama-server 进程  
ps aux | grep llama-server | grep -v grep  
```  
  
  
2、如何确认 CUDA 后端是否生效？  
  
执行以下命令检查：  
  
```  
# 1. 查看 Ollama 启动日志中的 GPU 后端信息  
sudo journalctl -u ollama | grep -E "(backend|GPU|cuda)" | tail -20  
  
# 2. 查看推理时的详细日志  
sudo journalctl -u ollama -f  
```  
  
  
  
3、验证推理速度  
  
运行测试看看实际速度：  
```  
# 测试推理速度  
ollama run qwen3.5:0.8b "介绍一下你自己" --verbose  
```  
  
4、为什么会使用 cpu 及 host memory  
  
如果调用了多个模型, 导致 gpu mem 塞不下一个模型 , 可能会使用 CPU mem 和 cpu + gpu 混合计算, 速度下降  
  
即使能全部塞下, 也会用到 cpu.  
  
  
5、为什么 CPU 使用率仍然很高？  
  
GPU 推理需要 CPU 辅助  
  
GPU 负责矩阵乘法（最耗时的部分），但以下工作仍然由 CPU 完成：  
```  
Token 生成调度：每生成一个 token，CPU 需要调用 GPU 执行  
  
Prompt 分词和编码：将文本转换为 token ID  
  
采样策略：从概率分布中选择下一个 token（如 top-p, temperature）  
  
KV Cache 管理：管理上下文缓存  
  
后处理：将生成的 token 解码为文本  
```  
  
结论：CPU 使用率高不代表 GPU 没在工作，而是混合计算模式的正常现象。

# 附录  
  
查看笔记本型号和硬件配置，可以使用以下命令：  
  
  
  
1. 查看笔记本型号  
  
```bash  
# 查看系统制造商和型号  
sudo dmidecode -s system-manufacturer  
sudo dmidecode -s system-product-name  
sudo dmidecode -s system-version  
  
# 或者一次性查看  
sudo dmidecode | grep -A 5 "System Information"  
```  
  
  
  
2. 查看 CPU 信息  
  
```bash  
# 查看 CPU 型号和核心数  
lscpu | grep -E "Model name|Socket|Core|Thread|CPU\(s\)"  
  
# 或者  
cat /proc/cpuinfo | grep "model name" | head -1  
```  
  
  
  
3. 查看内存信息  
  
```bash  
# 查看内存总量和速度  
sudo dmidecode -t memory | grep -E "Size|Speed|Type" | head -10  
  
# 或者  
free -h  
```  
  
  
  
4. 查看显卡信息  
  
```bash  
# NVIDIA 显卡  
nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv  
  
# 所有显卡  
lspci -nn | grep -E "VGA|3D|Display"  
```  
  
  
  
5. 查看磁盘信息  
  
```bash  
# 查看磁盘型号和大小  
sudo lshw -class disk | grep -E "description|product|size"  
  
# 或者  
lsblk -o NAME,SIZE,MODEL  
```  
  
  
  
6. 查看主板信息  
  
```bash  
sudo dmidecode -t baseboard | grep -E "Manufacturer|Product|Version"  
```  
  
  
  
7. 一键查看所有关键信息  
  
```bash  
echo "=== 系统信息 ==="  
sudo dmidecode -s system-manufacturer  
sudo dmidecode -s system-product-name  
  
echo -e "\n=== CPU ==="  
lscpu | grep "Model name"  
  
echo -e "\n=== 内存 ==="  
free -h  
  
echo -e "\n=== 显卡 ==="  
lspci -nn | grep -E "VGA|3D|Display"  
  
echo -e "\n=== NVIDIA 显卡 ==="  
nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv 2>/dev/null || echo "NVIDIA 驱动未安装"  
  
echo -e "\n=== 磁盘 ==="  
lsblk -o NAME,SIZE,MODEL | head -10  
```
