## 背景  

PG 18.6 跑着 pgmnemo extension 0.20.0、pgvector 0.8.6、pg_trgm 1.6 —— 这就够了。Claude Code 通过 MCP stdio JSON-RPC 把 `ingest` / `recall` / `search` / `stats` 四个 tool 接到 PG —— 但 pgmnemo schema 硬编码 `vector(1024)` —— 不是 384、不是 768、不是 1536 —— **必须 1024 维**。这台机器把这条路跑通了：**ollama 0.33.3 + qwen3-embedding:0.6b / 595.78M 参数 / Q8_0 量化 / 1024 维原生 / 639 MB** —— **pgmnemo schema 硬编码的 1024 维终于遇到原生匹配的 embedder** —— 没有 zero-pad、没有 padded1024、没有"384 维降级到 1024 维" 的 workaround —— **embedder 直接 1024 维, pgmnemo 直接吃**。

## 4. `pgmnemo.recall` MCP tool 端到端打通: ollama-native 1024 维

### 4.2 `config.py:embed()` 怎么调 ollama

```python
# pgmnemo_mcp/config.py 第 38-58 行 (简化版)
import requests

EMBEDDING_SERVER = os.getenv('EMBEDDING_SERVER', None)
EMBEDDING_MODEL = os.getenv('EMBEDDING_MODEL', None)
EMBEDDING_DIM = int(os.getenv('EMBEDDING_DIM', '1024'))

def embed(text: str) -> list[float]:
    """调 ollama /api/embeddings, 返回 EMBEDDING_DIM 维向量."""
    if not EMBEDDING_SERVER:
        return None  # 没配 → return None → recall 会 raise
    resp = requests.post(
        EMBEDDING_SERVER,
        json={'input': text, 'model': EMBEDDING_MODEL},
        timeout=30,
    )
    resp.raise_for_status()
    data = resp.json()
    vec = data['data'][0]['embedding']  # ollama /v1/embeddings 兼容 OpenAI 格式
    if len(vec) != EMBEDDING_DIM:
        return None  # 维度不匹配 → return None
    return [float(x) for x in vec]  # 显式转 numpy → Python float
```

**几个关键点**:

1. **EMBEDDING_SERVER 配 `http://127.0.0.1:11434/v1/embeddings`** —— ollama 从 0.1.x 起就支持 OpenAI-compatible `/v1/embeddings` 端点,跟 client 端代码无缝对接
2. **EMBEDDING_MODEL 配 `qwen3-embedding:0.6b`** —— 必须跟 `ollama list` 里的 model name 完全一致
3. **EMBEDDING_DIM 配 `1024`** —— 必须跟 ollama model details 的 `embedding_length` 一致
4. **`[float(x) for x in vec]`** —— 显式转 numpy → Python float,避免 `TypeError: Object of type float32 is not JSON serializable`(psycopg2 不接受 numpy 类型,见风险提示附录)

### 4.3 `server.py:recall()` 怎么把向量传给 SP

```python
# pgmnemo_mcp/server.py 第 158-178 行 (简化版)
def recall(query: str, top_k: int = 5, role: str = None, ...) -> str:
    query_vec = to_pgvector(embed(query))  # embed() 返回 1024-dim list[float]
    if query_vec is None:
        raise RuntimeError("embedding unavailable — check EMBEDDING_SERVER")
    cur.execute("""
        SELECT lesson_id, score, lesson_text, role, topic
        FROM pgmnemo.recall_fast(
            %s::vector,    -- 1024-dim vector 字面量
            %s,            -- top_k
            %s,            -- role filter
            %s,            -- min_importance
            %s,            -- topic_filter
            %s,            -- exclude_topics
            %s             -- alpha (HNSW vs BM25 混合权重)
        )
    """, (query_vec, top_k, role, min_importance, topic_filter, exclude_topics, alpha))
    return json.dumps(cur.fetchall())
```

**`to_pgvector(vec)` 怎么把 list[float] 转 PG 能接受的 vector 字面量**:

```python
def to_pgvector(vec: list[float]) -> str:
    """1024-dim float list → PG vector(1024) 字面量."""
    if vec is None:
        return None
    return '[' + ','.join(str(x) for x in vec) + ']'
    # → '[0.012,-0.034,...,0.567]' 格式 PG 解析成 vector(1024)
```

### 4.4 SP `recall_fast(vector, ...)` 端

```sql
-- pgmnemo extension SQL/recall_fast.sql (简化版)
CREATE FUNCTION pgmnemo.recall_fast(
    embedding vector,            -- ← pgmnemo 硬编码 vector(1024)
    top_k integer DEFAULT 5,
    role_filter text DEFAULT NULL,
    min_importance integer DEFAULT 1,
    topic_filter text DEFAULT NULL,
    exclude_topics text[] DEFAULT ARRAY[]::text[],
    alpha real DEFAULT 0.7
) RETURNS TABLE(lesson_id bigint, score real, lesson_text text, role text, topic text)
AS $$
BEGIN
    -- 第 34 行: dimension + NULL check
    IF embedding IS NULL OR vector_dims(embedding) != 1024 THEN
        RAISE EXCEPTION 'recall_fast: query_embedding must be vector(1024)';
    END IF;

    RETURN QUERY
    SELECT
        l.lesson_id,
        -- alpha 加权: HNSW cosine sim (1-distance) + BM25 ts_rank
        (alpha * (1 - (l.embedding <=> embedding))
         + (1 - alpha) * ts_rank(l.search_vector, plainto_tsquery('simple', 'PG 配置')))
            AS score,
        l.lesson_text, l.role, l.topic
    FROM pgmnemo.agent_lesson l
    WHERE l.embedding IS NOT NULL
      AND (role_filter IS NULL OR l.role = role_filter)
      AND l.importance >= min_importance
      AND (topic_filter IS NULL OR l.topic = topic_filter)
      AND NOT (l.topic = ANY(exclude_topics))
    ORDER BY l.embedding <=> embedding      -- HNSW 近似最近邻
    LIMIT top_k;
END;
$$ LANGUAGE plpgsql;
```

**SP 端的关键**:

- `vector_dims(embedding) != 1024` —— 维度硬编码检查 —— **这就是为什么 EMBEDDING_DIM 必须 1024**
- `<=>` —— pgvector cosine distance operator —— **HNSW index 自动接管**(索引建在 `embedding` 列上)
- `ts_rank + alpha 加权` —— hybrid 检索(向量 + 全文)
- **不需要 zero-pad** —— qwen3-embedding 原生 1024 维直通

**完整数据流**:

```text
Claude Code → MCP stdio JSON-RPC
  → pgmnemo-mcp server.py:recall()
    → config.py:embed()
      → HTTP POST http://127.0.0.1:11434/v1/embeddings
        → ollama 0.33.3 + qwen3-embedding:0.6b
        → 返回 1024-dim float32 array

```

**全程无 zero-pad** —— qwen3-embedding 原生 1024 维, pgmnemo schema 硬编码 1024 维, **两端原生匹配**。

## 5. 为什么 ollama qwen3-embedding 是当前最优解

**对比矩阵**:

| 维度 | ollama qwen3-embedding:0.6b | fastembed BAAI/bge-small-en-v1.5 (旧路径) | sentence-transformers BAAI/bge-small-zh-v1.5 |
|---|---|---|---|
| 维度 | **1024 原生** | 384 (需 zero-pad 到 1024) | 384 (需 zero-pad) |
| 模型大小 | 639 MB (Q8_0) | ~33 MB (ONNX) | ~93 MB (PyTorch) |
| 启动 | ollama serve 在跑 | 单独起 Python server | 单独起 Python server |
| 中文支持 | 多语言 (Qwen3) | 英文为主 | 中文 OK |
| 长上下文 | 32768 token | 512 token | 512 token |
| 安装复杂度 | `ollama pull qwen3-embedding:0.6b` | `pip install fastembed` + 写 48 行 server | `pip install sentence-transformers` + 写 server |
| 跟 pgmnemo schema 对接 | **零 workaround** | zero-pad 384→1024 (5 行) | zero-pad (5 行) |
| 推理性能 | ollama 内部 llama.cpp + CPU | fastembed ONNX + CPU | sentence-transformers PyTorch + CPU |
| 显存需求 | ollama 模型 cache + llama.cpp | 仅 ONNX runtime | PyTorch + 模型权重 |

**结论**:

- **如果 pgmnemo schema 是 1024 维** —— ollama qwen3-embedding 是 **零 workaround** 的最优解
- **如果 pgmnemo schema 是别的维度**(比如 384) —— 退而求其次选 fastembed,client 端做 zero-pad
- **如果需要中文 + 384 维** —— sentence-transformers BAAI/bge-small-zh-v1.5,client 端 zero-pad

## 7. 三种 MCP server 暴露的工具分别干啥

| Tool | 后端 SP | 输入 | 输出 |
|---|---|---|---|
| `pgmnemo.ingest` | `pgmnemo.ingest_lesson` | role + topic + lesson_text + commit_sha + ... | lesson_id (真写入) |
| `pgmnemo.recall` | `pgmnemo.recall_fast` | query + top_k + role + min_importance + topic_filter + exclude_topics + alpha | lesson_id + score + lesson_text + role + topic (HNSW + BM25 hybrid) |
| `pgmnemo.search` | `pgmnemo.search_lessons` | query + top_k + role + min_importance | lesson_id + score + lesson_text (BM25-only) |
| `pgmnemo.stats` | `pgmnemo.stats` | (no args) | total_lessons, by_role, by_topic, by_importance, recent_24h |

**注意**: `pgmnemo.recall` MCP tool 走 `recall_fast` SP —— `recall_fast` **强制要 vector** —— 没有 text-only fallback。所以要么配 EMBEDDING_SERVER,要么用 `pgmnemo.search` (BM25-only fallback) 或直接 SQL `recall_lessons`。

## 10. 几个值得提前知道的边界条件

1. **`pgmnemo.recall` MCP tool 没有 text-only fallback** —— `recall_fast` 强制要 vector;要么起 EMBEDDING_SERVER(本文 ollama 路径),要么让 agent 用 `pgmnemo.search` 或 SQL `recall_lessons`
2. **EMBEDDING_DIM 必须跟 ollama model 的 embedding_length 完全一致** —— `qwen3-embedding:0.6b` 是 1024 维,配 1024;换 model(如 `nomic-embed-text` 是 768 维)要同步改 EMBEDDING_DIM,否则 `config.py:embed()` 第 41 行 `len(vec) != EMBEDDING_DIM` 返回 None
3. **`pgmnemo.ingest` 在没传 commit_sha 时会被 gate_strict='enforce' 挡** —— 生产用要么传 commit_sha,要么 session 里 `SET pgmnemo.gate_strict = 'warn'` 或 `'off'`
4. **version 字段不一致** —— PyPI 0.20.0 / `__init__.py` 0.20.0 / `pgmnemo.get_params` 0.10.0 —— 不影响功能,issue tracker 应有 PR
5. **numpy 类型不能直接 psycopg2** —— `json.dumps` numpy.float32 抛 `TypeError` —— `config.py:embed()` 必须 `[float(x) for x in vec]` 显式转

## 11. 给 MCP server 加你自己的 hook (如果不想走 MCP)

如果你的 agent runtime 不是 Claude Code,只要它能跑 Python,可以直接 import pgmnemo MCP server 的核心函数:

```python
import sys
sys.path.insert(0, '/opt/sbert/lib/python3.13/site-packages')
from pgmnemo_mcp.config import embed
from pgmnemo_mcp.db import get_conn, to_pgvector

# 不走 MCP,直接 embed + SQL
conn = get_conn()
cur = conn.cursor()
vec = embed("PG 18.6 装 pgmnemo")
cur.execute("""
    SELECT lesson_id, score, lesson_text, role, topic
    FROM pgmnemo.recall_fast(%s::vector, 5, NULL, 1, NULL, ARRAY[]::text[], 0.7)
""", (to_pgvector(vec),))
print(cur.fetchall())
```

**核心三个函数**:

- `embed(text)` —— 调 ollama,返回 1024-dim float list
- `to_pgvector(vec)` —— float list → PG vector 字面量
- `get_conn()` —— 从 DATABASE_URL env 拿 psycopg2 connection

## 写在最后

`pgmnemo-mcp` 是个把 Claude Code 接进 PG 的 MCP server,加上 ollama 0.33.3 + qwen3-embedding:0.6b,**整条链路都是"PG 原生 1024 维"**:pgmnemo schema 硬编码 vector(1024) ↔ ollama model details embedding_length=1024 ↔ EMBEDDING_DIM env 配 1024 ↔ `recall_fast` SP 第 34 行 `vector_dims != 1024` 检查。

**没有 zero-pad、没有 padded1024、没有"384 维降级到 1024 维"的 workaround** —— 这是 2026-09 这台机器上能跑的最干净 pgmnemo-mcp 路径。

**姊妹篇 1 (修订 v3) 标记: ollama-native 1024 维版** —— 之前所有"fastembed + zero-pad"版本的 workaround 都不再需要。后续姊妹篇 2 (benchmark) + 姊妹篇 3 (川序) 都基于 ollama-native 1024 维统一路径。
