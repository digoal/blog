## 2. Embedder 怎么选: 4 种 trade-off

pgmnemo benchmark 跑过 4 个 embedder, **每个在仓库有专门 addenda** —— 记 trade-off:

| Embedder | 维度 | License | 商用 OK? | 推荐场景 | 跟 pgmnemo schema 对接 |
|---|---|---|---|---|---|
| `facebook/dragon-plus` (Lin et al. 2023) | 768d (zero-pad 到 1024d) | CC-BY-NC | ❌ non-commercial | LoCoMo **paper-canonical** | zero-pad (数学等价证明见 §2.1) |
| `BAAI/bge-m3` (Chen et al. 2024) | 1024d | MIT | ✅ | LongMemEval 主力, **生产可用** | 原生 1024 维直通 |
| `dunzhang/stella_en_1.5B_v5` | 1024d (推测) | Apache-2.0 | ✅ | 高质量 long-context | 原生 1024 维直通 |
| **`qwen3-embedding:0.6b` via ollama** | **1024d 原生** | Apache-2.0 | ✅ | **现代最简生产路径**(姊妹篇 1 同源) | **原生 1024 维直通, 零 workaround** |

**paper-canonical embedder 选哪个** —— 按你要复现的 paper 走。**LoCoMo 原 paper 用 DRAGON** —— pgmnemo 必须用 DRAGON 才能跟 paper baseline 对得上。**LongMemEval 原 paper 用 text-embedding-3-large** —— 但 pgmnemo 实际跑 `BAAI/bge-m3`(生产可用 + 不调 OpenAI API 省钱)。

**modern 最简 embedder 选哪个** —— 2026-09 起 ollama 0.33.3 + qwen3-embedding:0.6b 是新选项 —— 跟姊妹篇 1 pgmnemo-mcp 完全同源 —— **1024 维原生 + 不需要 model download 阻塞 + 跟 pgmnemo schema 硬编码 vector(1024) 完美对齐**。

### 2.1 DRAGON 768d → 1024d 的 zero-pad 数学等价

**这是 paper-canonical 学术对标的硬要求** —— LoCoMo paper 用 DRAGON, 我们必须用 DRAGON + zero-pad 才能跟 paper baseline 比。

`benchmarks/locomo/ADDENDA/LOCOMO_EMBEDDER_PADDING.md` 给的证明:

```python
DRAGON output a ∈ ℝ^768
pgmnemo storage a' = pad(a, 1024) = [a_1, ..., a_768, 0, 0, ..., 0]

For cosine similarity:
cos(a', b') = (a' · b') / (‖a'‖ · ||b'||)
            = (a · b + Σᵢ 0·0) / (sqrt(||a||² + Σᵢ 0²) · sqrt(||b||² + Σᵢ 0²))
            = (a · b) / (||a|| · ||b||)
            = cos(a, b)
```

**Zero-padding 保留 cosine similarity 精确** —— HNSW(`vector_cosine_ops`)最近邻顺序不变。**这是 paper-canonical benchmark 的硬要求** —— **如果用 BGE-M3 (1024d) 跑 LoCoMo, 数字和 paper 不直接可比**。

**用 ollama 跑 benchmark 的关键调用**:

```python
import requests

def embed_ollama(text: str, model: str = 'qwen3-embedding:0.6b') -> list[float]:
    """调 ollama /api/embed (新版), 返回 1024-dim float list."""
    resp = requests.post(
        'http://127.0.0.1:11434/api/embed',
        json={'model': model, 'input': text},
        timeout=30,
    )
    resp.raise_for_status()
    return [float(x) for x in resp.json()['embeddings'][0]]
```

**对比 DRAGON / BGE-M3 的差异**:

- **DRAGON**: `from transformers import AutoModel; m = AutoModel.from_pretrained('facebook/dragon-plus'); vec = m(**tok(text, return_tensors='pt')).last_hidden_state.mean(dim=1).detach().numpy()` —— **768 维 → 需 zero-pad 256 个 0**
- **BGE-M3**: `from FlagEmbedding import BGEM3FlagModel; m = BGEM3FlagModel('BAAI/bge-m3'); vec = m.encode([text])['dense_vecs'][0]` —— **1024 维原生**
- **Stella V5**: `model = sentence_transformers.SentenceTransformer('dunzhang/stella_en_1.5B_v5'); vec = model.encode(text)` —— **1024 维原生**
- **ollama qwen3-embedding**: 上面的 `embed_ollama()` —— **1024 维原生, 但通过 HTTP API, 不直接 in-process**

### 2.3 Stella V5 是个特殊 case

`benchmarks/longmemeval/requirements.txt` 里 **pin `transformers==4.44.2`**:

```
# Pin for Stella V5 compatibility: transformers 5.x removed Qwen2Config.rope_theta
# (absorbed into config.rope_parameters["rope_theta"]); bundled modeling_qwen.py
# in dunzhang/stella_en_1.5B_v5 requires the 4.x direct-attribute form.
# See benchmarks/longmemeval/ADDENDA/LONGMEMEVAL_EMBEDDER_STELLA.md
transformers==4.44.2
```

**Stella V5 用了 dunzhang 自带的旧 `modeling_qwen.py`** —— **依赖 transformers 4.x 的 `Qwen2Config.rope_theta` 直接属性** —— **5.x 改成了 `rope_parameters["rope_theta"]`** —— 升级 transformers 会让 Stella V5 加载就 fail。**这就是为什么 pgmnemo 把 transformers 4.44.2 pin 在 requirements.txt** —— **version drift 是个真问题**。

## 3. 灌进 pgmnemo: 4 个 runner, 按版本区分

`benchmarks/scripts/` 24 个 Python 脚本 —— **4 个核心**按版本区分:

| Runner | 版本 | 大小 | 用途 |
|---|---|---|---|
| `run_locomo_bench.py` | v0.2.1+ | 436 行 | LoCoMo turn-level (segment-level primitive) |
| `run_locomo_bench_session.py` | v0.2.1+ | 529 行 | LoCoMo session-level (paper-canonical) |
| `run_longmemeval_pgmnemo_full.py` | v0.2.1 | ? | LongMemEval full pipeline |
| `run_longmemeval_pgmnemo_v030.py` | v0.3.0+ | ? | LongMemEval w/ MPS + max_seq=512 fix |

**Session-level runner 的差异** —— **turn-level 调一次 `recall_lessons(lesson_text)`**, **session-level 调多次再 merge** —— paper-canonical session-level 是 LoCoMo 真正的 metrics:

```python
# session-level (简化版)
for session_id in locomo_sessions:
    session_dialogue = sessions[session_id]   # 600 turns
    for turn in session_dialogue:
        pgmnemo.ingest(role=turn['role'], topic=session_id,
                        lesson_text=turn['text'])
    for question in locomo_questions[session_id]:
        expected_answer = question['answer']
        recalled = pgmnemo.recall_lessons(query=question['query'],
                                          role=turn['role'],
                                          top_k=10)
        scores[question['id']] = recall_at_k(expected_answer, recalled)
```

**segment-level primitive** 是给 **CI / smoke test** 用的 —— 1 个 turn ingest + 1 个 query recall —— 几秒钟跑完 —— **不能跟 paper baseline 直接比**(paper 报 session-level aggregate)。

### 3.1 ollama runner 模板 (新)

**如果用 ollama qwen3-embedding 跑 LoCoMo session-level**:

```python
# /path/to/pgmnemo/benchmarks/scripts/run_locomo_bench_session_ollama.py
# 跟 DRAGON runner 同结构, 仅替换 embed() 函数
import os
import json
import requests
import psycopg2

def embed_ollama(text: str) -> list[float]:
    """ollama qwen3-embedding:0.6b → 1024-dim."""
    resp = requests.post(
        'http://127.0.0.1:11434/api/embed',
        json={'model': 'qwen3-embedding:0.6b', 'input': text},
        timeout=30,
    )
    resp.raise_for_status()
    return [float(x) for x in resp.json()['embeddings'][0]]

# 调 pgmnemo extension
conn = psycopg2.connect(os.environ['DATABASE_URL'])
cur = conn.cursor()

# ingest 全部 turn
for session_id, turns in locomo_sessions.items():
    for turn in turns:
        vec = embed_ollama(turn['text'])
        cur.execute("""
            INSERT INTO pgmnemo.agent_lesson
                (role, topic, lesson_text, importance, embedding)
            VALUES (%s, %s, %s, %s, %s::vector)
            ON CONFLICT (lesson_id) DO NOTHING
        """, (turn['role'], session_id, turn['text'], 5, vec))
conn.commit()

# recall 全部 question
for q in locomo_questions:
    qvec = embed_ollama(q['query'])
    cur.execute("""
        SELECT lesson_id, lesson_text, role, topic,
               1 - (embedding <=> %s::vector) AS cosine_sim
        FROM pgmnemo.agent_lesson
        ORDER BY embedding <=> %s::vector LIMIT 10
    """, (qvec, qvec))
    results = cur.fetchall()
    # judge LLM 评估 recall@10 (没 judge layer 数字不准)
    scores[q['id']] = recall_at_k(q['answer'], [r[1] for r in results])
```

**关键差异 vs DRAGON runner**:

1. **`embed_ollama()` 走 HTTP** —— DRAGON runner 走 in-process transformers
2. **`embedding_length=1024` 直通** —— DRAGON runner 需要 `pad_to_1024(vec)`
3. **ctx=32768 长对话天然支持** —— DRAGON runner 要分 chunk (max_seq=512)
4. **judge layer 仍然要** —— **没有 judge 的 recall@10 数字不能跟 paper 比**(paper 用 GPT-4 judge 评估答案正确性)

### 3.2 BM25-only baseline (不调 LLM)

```python
# run_nollm.py 简化版
def recall_bm25_only(query: str, role: str = None, top_k: int = 10) -> list:
    cur.execute("""
        SELECT lesson_id, lesson_text,
               ts_rank(search_vector, plainto_tsquery('simple', %s)) AS rank
        FROM pgmnemo.agent_lesson
        WHERE search_vector @@ plainto_tsquery('simple', %s)
          AND (%s IS NULL OR role = %s)
        ORDER BY rank DESC LIMIT %s
    """, (query, query, role, role, top_k))
    return cur.fetchall()
```

**BM25-only baseline 不调 LLM** —— **zero API spend** —— **CI 跑得动** —— **不跟 paper 比**(paper 用 HNSW + dense embed)。

## 5. 验算: significance_test + significance_test_extended + CI gate

### 5.1 scripts/significance_test.py — 双 metrics 对比

```bash
python /root/new/src/pgmnemo/scripts/significance_test.py \
    /root/new/src/pgmnemo/benchmarks/locomo/results/v0.20.0_session_20260905/metrics.json \
    /root/new/src/pgmnemo/benchmarks/locomo/results/v0.18.0_session_20260501/metrics.json

# Exit code:
# 0 — 显著提升，无回归
# 1 — 无显著提升，或回归
```

**significance_test 跑**:

- **Wilson 95% CI** for recall@K
- **McNemar test** for paired binary (recall hit / miss)
- **Bonferroni α=0.01** for multiple categories
- **Cohen's h** for effect size

### 5.2 scripts/significance_test_extended.py — Per-category + CI gate

```bash
python /root/new/src/pgmnemo/scripts/significance_test_extended.py \
    /root/new/src/pgmnemo/benchmarks/locomo/results/v0.20.0_session_20260905/metrics.json \
    /root/new/src/pgmnemo/benchmarks/locomo/results/v0.18.0_session_20260501/metrics.json

# Exit codes:
#   0 — neutral (OK to ship)
#   1 — significant improvement (OK to ship with claim)
#   2 — SIGNIFICANT REGRESSION (BLOCK release)
#   3 — near-threshold cells (WARN)
```

**Extended test 跑 per-category** (single-hop / multi-hop / temporal / open-domain) —— **任何一个 category 显著回归 → exit code 2 → release 必被拦**。

### 5.3 .github/workflows/release.yml — Gate 必过

## 6. PREREG (pre-registration) 机制 —— v0.20.0 的范本

### 6.1 背景

PREREG = **把实验的 hypothesis + 独立变量 + 数据集 + 统计检验 + 决策规则提前 freeze** —— 实验结束后再回填结果 —— **防止 hindsight bias** —— **注册了的实验不能改 hypothesis 或 cherry-pick 数据**。

**AI 极客视角** —— vendor SaaS 永远不会说"我们 8 月 20 日注册了一个 PREREG 准备测 graph expansion" —— pgmnemo 把"什么时候跑什么"和"跑出来什么"分两步 publish。

### 6.2 v0.20.0 gate 的 algebraic carry-forward

```json
{
  "version": "v0.20.0",
  "carry_forward": [
    {
      "from": "v0.18.1",
      "metric": "locomo_recall@10_session",
      "value": 0.8409,
      "prereg_sha": "4eb3a2b8..."
    },
    {
      "from": "v0.18.1",
      "metric": "longmemeval_recall@10",
      "value": 0.9334,
      "prereg_sha": "ab12cd34..."
    }
  ],
  "ablation": {
    "PREREG_020_EXPAND": {
      "scope": "graph expansion quality",
      "control_metric": "locomo_recall@10_session",
      "treatment": "graph_expansion=True",
      "hypothesis": "H1: +2pp at category multi-hop"
    }
  }
}
```

**11 步 algebraic carry-forward proof** 在 `gate/v0.20.0.json` —— 每个 metric 都有 prereg_sha 关联到当时的 PREREG 文件 —— **不是这次 release 临时测的**。

### 6.3 PREREG 文件应该在哪

**pgmnemo 的 PREREG 注册流程**(推测, 因没在 main branch 找到 PREREG 文件):

```bash

cat > spec/graphrag/PREREG_020_EXPAND_2026-08-20.md << 'EOF'
# PREREG_020_EXPAND — pgmnemo 0.20.0 graph expansion quality ablation

**Registered at**: 2026-08-20 by @author
**pgmnemo version under test**: v0.20.0
**Embedder**: BAAI/bge-m3 (1024d)
**Datasets**: LoCoMo session-level + LongMemEval

## Hypotheses
- H1: graph_expansion=True improves multi-hop recall@10 by ≥2pp
- H0: no improvement

## Independent Variables
- graph_expansion (True/False)

## Datasets
- LoCoMo 10 dialogues session-level (paper-canonical)

## Statistical Test
- McNemar paired test
- Wilson 95% CI

## Blinding
- bench runner doesn't see prereg_sha
- statistical test runner doesn't see hypothesis
EOF

# 2. SHA-256 freeze

# 4eb3a2b8...

# 3. PREREG file 关联到 gate
# (实际流程可能用 GitHub Issue / private repo 注册, main branch 没见到 spec/ 目录)
```

## 8. 三条跟 vendor 不同的纪律

**跑完 pgmnemo 的 bench 设施, 对比 vendor SaaS 的"我们 recall 是 X%"** —— AI 极客会发现 3 条 vendor 几乎做不到的事:

1. **dataset sha256 在 metrics.json** —— vendor SaaS 不告诉你 corpus 是什么、checksum 是什么、哪天跑的 —— pgmnemo 全部 in-band
2. **CI gate 必过 release tag** —— vendor SaaS 升级前不跑 bench —— 或者跑了不发 —— pgmnemo 的 `gate/v<X.Y.Z>.json` 是 release blocker
3. **PREREG 把 hypothesis 提前 freeze** —— vendor SaaS 永远不会说"我们 8 月 20 日注册了一个 PREREG 准备测 graph expansion" —— pgmnemo 把"什么时候跑什么"和"跑出来什么"分两步 publish —— **防止 hindsight bias**

**第三条是 AI 极客视角下最值得学的事** —— **vendor marketing 永远不会告诉你他们 hypothesis 是怎么选的、analysis plan 是怎么写的** —— pgmnemo 把这层透明开放 —— **你也可以学这套流程给你自己的 ML 实验**。
