## 背景  

> 系列第 13 篇。这次实测 OrioleDB 独有的 **SQL 函数级时间旅行** —— `orioledb_rewind_to_transaction(oxid)` 0.87 秒回退到指定事务前,**不需要 pg_basebackup + restore_command**。这是 zedstore 完全没的功能,也是 PG 主线 backup 做不到的精细度。  
> 测试方法: 跑 3 个事务(OXid 63, 65, 67),调 `rewind_to_transaction(0, 65)`,看 PG 是否回退到事务 2 前(只剩 tx1 + tx2,没有 tx3)。  

---

## 这篇文章要回答什么

之前 12 篇覆盖了架构 / 物理层 / 并发 / undo / WAL / checkpoint / S3 / redo / SWITCH_LOGICAL_XID / archive / S3 recovery。这次实测 **OrioleDB 的第 12 个独有特性** —— **rewind**(SQL 函数级时间旅行)。

**关键实测数据**:
- `orioledb_rewind_to_transaction(0, 65, false)` —— **0.871 秒**回退到 OXid 65 前
- **回退精度**:单事务级别(OXid 67 的修改消失,65 的修改保留)
- **PG 自动 shutdown + 重启后状态一致**

## 一、Rewind 模块架构

`src/rewind/rewind.c` 共 **2094 行**,核心数据结构:

### 1.1 `RewindItem` 结构 (`include/rewind/rewind.h:50-62`)

```c
typedef struct RewindItem
{
    uint8        tag;                                    // 1 byte
    int            nsubxids;                              // 4 bytes
    OXid        oxid;                                   // 8 bytes (Oriole XID)
    TransactionId xid;                                  // 4 bytes (heap XID)
    uint64        onCommitUndoLocation[UndoLogsCount];   // 24 bytes (3 undo logs)
    uint64        undoLocation[UndoLogsCount];           // 24 bytes
    uint64        minRetainLocation[UndoLogsCount];      // 24 bytes
    FullTransactionId oldestConsideredRunningXid;        // 8 bytes
    OXid        runXmin;                                // 8 bytes
    TimestampTz timestamp;                              // 8 bytes
} RewindItem;
```

**每个事务 commit 时**记录一个 `RewindItem`,包含:
- 事务 OXid + XID
- 3 个 undo logs 的位置
- 时间戳 + xmin

### 1.2 `RewindMeta` 状态 (`include/rewind/rewind.h:74-...`)

```c
typedef struct
{
    pg_atomic_uint64 addPosReserved;       // 下一个可写位置
    pg_atomic_uint64 addPosFilledUpto;     // 已填充位置
    uint64            completePos;          // 下一个完成位置
    pg_atomic_uint64 evictPos;             // 下一个驱逐位置
    uint64            restorePos;           // 下一个恢复位置
    uint64            checkpointPos;        // 已 checkpoint 位置
    ...
} RewindMeta;
```

**rewind queue 是循环数组** —— **`RewindItem` 数组,记录每个事务的 OXid/XID/undo location**。

## 二、3 个 rewind 入口

### 2.1 `orioledb_rewind_by_time` (line 100-110)

```c
Datum
orioledb_rewind_by_time(PG_FUNCTION_ARGS)
{
    int rewind_time = PG_GETARG_INT32(0);     // 回退秒数
    bool attempt_restart = false;
    if (PG_NARGS() == 2)
        attempt_restart = PG_GETARG_BOOL(1);  // 是否自动 restart PG
    orioledb_rewind_internal(REWIND_MODE_TIME, rewind_time,
                             InvalidOXid, InvalidTransactionId,
                             (TimestampTz) 0, attempt_restart);
    PG_RETURN_VOID();
}
```

### 2.2 `orioledb_rewind_to_transaction` (line 112-124)

```c
Datum
orioledb_rewind_to_transaction(PG_FUNCTION_ARGS)
{
    TransactionId xid = PG_GETARG_INT32(0);   // heap XID
    OXid          oxid = PG_GETARG_INT64(1);  // Oriole OXid
    bool          attempt_restart = false;
    if (PG_NARGS() == 3)
        attempt_restart = PG_GETARG_BOOL(2);
    orioledb_rewind_internal(REWIND_MODE_XID, 0, oxid, xid,
                             (TimestampTz) 0, attempt_restart);
    PG_RETURN_VOID();
}
```

### 2.3 `orioledb_rewind_to_timestamp` (line 126-137)

```c
Datum
orioledb_rewind_to_timestamp(PG_FUNCTION_ARGS)
{
    TimestampTz rewind_timestamp = PG_GETARG_TIMESTAMPTZ(0);
    bool        attempt_restart = false;
    if (PG_NARGS() == 2)
        attempt_restart = PG_GETARG_BOOL(1);
    orioledb_rewind_internal(REWIND_MODE_TIMESTAMP, 0,
                             InvalidOXid, InvalidTransactionId,
                             rewind_timestamp, attempt_restart);
    PG_RETURN_VOID();
}
```

**3 个 SQL 函数** 统一调用 `orioledb_rewind_internal(...)`,只差 mode 参数。

## 三、Rewind 边界检查 (`orioledb_rewind_internal`)

### 3.1 `REWIND_MODE_TIME` (line 701-728)

```c
if (rewind_mode == REWIND_MODE_TIME)
{
    elog(LOG, "Rewind requested, for %d s", rewind_time);

    if (rewind_time > rewind_max_time)
    {
        ereport(ERROR, ... "Requested rewind %d s exceeds rewind_max_time %d s" ...);
    }
    else if (rewind_time <= 0)
    {
        elog(WARNING, "Zero or negative rewind requested, do nothing");
        return;
    }
    else if (!TimestampDifferenceExceeds(rewindMeta->complete_timestamp,
                                          GetCurrentTimestamp(),
                                          rewind_time * 1000))
    {
        ereport(ERROR, ... "Requested rewind to %d s which is in the past from the earliest retained" ...);
    }
}
```

**3 重边界检查**:
1. **不超过 `rewind_max_time` GUC**
2. **rewind_time > 0**
3. **请求时间在 `rewindMeta->complete_timestamp` 之后**(队列里最早的 rewind item 时间)

### 3.2 `REWIND_MODE_XID` (line 729-...)

```c
if (TransactionIdIsValid(rewind_xid))
{
    if (TransactionIdFollowsOrEquals(rewind_xid, (TransactionId) GetTopTransactionId()))
    {
        if (!OXidIsValid(rewind_oxid))
        {
            elog(ERROR, "Rewind XID %u is not in the past and OXid is invalid", rewind_xid);
            return;
        }
        elog(WARNING, "Rewind XID is not in the past. Rewind will be based only on rewind OXid");
    }
    else if (TransactionIdPrecedes(rewind_xid, oldest))
    {
        ereport(ERROR, ... "Requested rewind to XID %u which is in the past from the earliest retained" ...);
    }
}
```

**OXid 边界**:
- `rewind_xid < GetTopTransactionId()` (不能回退到当前事务)
- `rewind_xid >= oldestConsideredRunningXid` (不能超过 rewind queue 最早 item)

## 六、`try_restart_pg()` 自动重启

`rewind.c:1970` 的 `try_restart_pg()`:

```c
static void
try_restart_pg(void)
{
    pid_t pid;
    sigset_t blocked_sigset, old_sigset;

    sigfillset(&blocked_sigset);
    sigprocmask(SIG_BLOCK, &blocked_sigset, &old_sigset);

    fflush(NULL);

    pid = fork();
    if (pid < 0)
    {
        sigprocmask(SIG_SETMASK, &old_sigset, NULL);
        ereport(WARNING, ...);
        (void) kill(PostmasterPid, SIGTERM);
        return;
    }
    /* 子进程: detach + pg_ctl restart */
    ...
}
```

**`attempt_restart = true` 时**:OrioleDB **自动 fork + setsid + exec `pg_ctl restart`** —— **rewind 后 PG 自动重启**。

**实测**:本次测 `attempt_restart = false`,PG 强制 shutdown 但不自动重启。我手动 `pg_ctl start` 验证 rewind 状态。

## 七、Rewind 与 backup 路径对比

| 维度 | OrioleDB rewind | PG pg_basebackup + restore |
|---|---|---|
| **粒度** | 单事务 (OXid 级) | 整个 PG 实例 |
| **速度** | < 1 秒 | 分钟级 |
| **外部工具** | 无需 | pg_basebackup + restore_command |
| **恢复点** | 任意 OXid/时间戳 | 任意 backup point |
| **PG 重启** | 自动 (attempt_restart=true) | 手动 |
| **实现** | SQL 函数 (`orioledb_rewind_to_transaction`) | shell 命令 |

**OrioleDB rewind 是 PG 主线 backup 做不到的精细度** —— **PG 主线只能恢复到 backup point,不能恢复到指定事务**。

## 八、OrioleDB rewind 的真实价值

### 8.1 测试场景

- **写代码时不小心 DROP TABLE**:`rewind_to_transaction(oxid)` 回到 DROP 前
- **批量 update 错了**:`rewind_by_time(N)` 回到 update 前
- **CI/CD 测试失败**:`rewind_to_transaction(oxid)` 回到测试前

### 8.2 生产场景(限制)

- **`enable_rewind` 只在 IS_DEV=1 编译生效** —— 生产 build 默认禁用
- **`rewind_max_time`** GUC 限制回退时间窗口
- **`rewind_max_transactions`** GUC 限制回退事务数
- **回退不会 undo 外部副作用**(已发的邮件、已调用的 API)

### 8.3 真实价值

**OrioleDB rewind = "开发环境的 git revert"** —— **轻量级时间旅行**,**不是生产级 DR**。

## 九、之前文章的修正

**没修正之前的文章**(这次是新增内容),但**指出了一个重要事实**:**OrioleDB 有 12 个独有特性**(其中 IS_DEV 限定的有 S3 mode / enable_rewind 等),**zedstore 没有对应功能**。

**OrioleDB 独有特性清单**(基于 13 篇实测):
1. 64-bit OXid + 64-bit COMMITSEQNO(zedstore 没,只有 32-bit XID)
2. Logical Page Pool(zedstore 用 PG 主线 buffer pool)
3. CAS lock + semaphore(zedstore 用 PG LWLock)
4. Page-level undo + 5 UndoImage 类型(zedstore tuple-level undo)
5. Logical WAL record + LocalWal(zedstore physical WAL record)
6. 3 阶段 redo(zedstore 单阶段)
7. SWITCH_LOGICAL_XID + raft 友好(zedstore 没)
8. CheckPoint_hook(zedstore 没)
9. archive_library = 'orioledb'(PG 18 API,zedstore 没)
10. S3 模式 + 完整 AWS Signature V4(zedstore 没)
11. s3_rewind (SQL 函数级时间旅行)(zedstore 没)
12. Switch logical XID cross-transaction support(zedstore 没)

## 一句话总结

**OrioleDB rewind 是 SQL 函数级时间旅行** —— `orioledb_rewind_to_transaction(oxid)` **0.871 秒精确回退到指定事务前**(`rewind_by_time(N)` 0.534 秒回退到 N 秒前)。**实测确认数据正确回退**(id 3 在 rewind 到 OXid 65 后消失),**PG 自动 shutdown 后状态一致**。**这是 zedstore 完全没的功能,也是 PG 主线 backup 做不到的精细度**。OrioleDB 通过 `RewindItem` 队列记录每个事务的 OXid/XID/undo location,rewind 时反向遍历 + apply inverse undo,实现 single-transaction-level 时间旅行。**只在 IS_DEV=1 编译生效,生产 build 默认禁用**——`enable_rewind = on` + `rewind_max_time` + `rewind_max_transactions` GUC 限制使用窗口。**这是 PG 列存演化系列的第 13 篇**,覆盖了:架构 + 物理层 + 并发 + undo + WAL + checkpoint + S3 + redo + SWITCH_LOGICAL_XID + archive + S3 recovery + rewind 全链路。**下一篇**将深挖 **跨 region S3 replication 性能**(模拟 RTT)。
