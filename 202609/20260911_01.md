## 主问题的答案

**关键事实**: **VARCHAR2 不是"变成 VARCHAR"** 。

VARCHAR2 和 VARCHAR **在 IvorySQL/Oracle 兼容层里是两个不同的类型**(不同的 OID,pg_type 里有独立条目)。

```
VARCHAR2 = ORAVARCHARCHAROID  (Oracle 风格)
VARCHAR  = VARCHAROID         (PG 原生)
```

"转换"实际上只是**运算符解析时** Oracle 模式优先选 Oracle 类型作为结果。
PG 原生类型不会被破坏 — 它一直在那。

## 1. 为什么需要"转换"

PG 原生有个特性: **算子必须严格匹配参数类型**:

```sql
-- 这在 PG 报错(没有 varchar2 || varchar 算子)
SELECT 'a'::varchar2 || 'b'::varchar;
```

但 Oracle 允许 VARCHAR2 和 VARCHAR 混用。IvorySQL 怎么模拟?

→ **hook PG 的"算子精确查找"函数**,在 PG 找不到匹配时,**主动用 Oracle 的类型优先级规则**把参数转成 Oracle 类型。

## 2. 触发点 — `parse_oper.c:binary_oper_exact`

`src/backend/parser/parse_oper.c:271`:

```c
static Oid
binary_oper_exact(List *opname, Oid arg1, Oid arg2)
{
    Oid result;

    // 处理 UNKNOWN 短路 ...

    // 第 1 步:用原参数类型找算子
    result = OpernameGetOprid(opname, arg1, arg2);
    if (OidIsValid(result))
        return result;  // 找到了,直接返回

    // 第 2 步:精确匹配失败 → 触发 Oracle 兼容 hook
    if (oracle_datatype_precedence_hook && ORA_PARSER == compatible_db)
    {
        bool rewrite_args = false;
        char *opname_str;
        Oid result_arg1, result_arg2;

        DeconstructQualifiedName(opname, &schemaname, &opname_str);

        // 调用 Oracle 类型转换 hook
        rewrite_args = (*oracle_datatype_precedence_hook)(
            arg1, arg2, opname_str, &result_arg1, &result_arg2);

        if (rewrite_args)
        {
            arg1 = result_arg1;   // 改写后的类型
            arg2 = result_arg2;

            // 用改写后的类型再找一次算子
            result = OpernameGetOprid(opname, arg1, arg2);
            if (OidIsValid(result))
                return result;
        }
    }

    return InvalidOid;  // 还是没找到,后续 PG 流程自己处理
}
```

**关键点**:
- hook **只在 Oracle 模式 + 精确匹配失败时才触发**
- 触发后只是**改写 arg1 / arg2 的 OID**,**不修改 SQL 文本**
- 用改写后的 OID 再找一次算子

## 3. hook 实现 — `compatible_oracle_precedence.c`

`contrib/ivorysql_ora/src/datatype/compatible_oracle_precedence.c:109`:

```c
bool
pg_compatible_oracle_precedence(Oid arg1, Oid arg2,
                                 char *opname_p,
                                 Oid *result_arg1, Oid *result_arg2)
{
    // 1. UNKNOWN(字面量)默认按 Oracle CHAR 处理
    if (arg1 == UNKNOWNOID) arg1 = ORACHARCHAROID;
    if (arg2 == UNKNOWNOID) arg2 = ORACHARCHAROID;

    // 2. Domain 类型降级到基础类型
    arg1 = getBaseType(arg1);
    arg2 = getBaseType(arg2);

    bool arg1_is_oracle = parameter_in_priorityarray(arg1);
    bool arg2_is_oracle = parameter_in_priorityarray(arg2);

    // 3. 双方都是 Oracle 类型 → 走 precedence 选择
    if (arg1_is_oracle && arg2_is_oracle) {
        // 见 §4
    }
    // 4. arg1 是 Oracle, arg2 是 PG → 把 PG 转 Oracle
    else if (arg1_is_oracle) {
        switch(arg2) {
            case BPCHAROID:       arg2 = ORACHARCHAROID; break;
            case VARCHAROID:      arg2 = ORAVARCHARCHAROID; break;  // ← 这里!
            case NUMERICOID: ...  arg2 = NUMBEROID; break;
            case FLOAT4OID:       arg2 = BINARY_FLOATOID; break;
            case FLOAT8OID:       arg2 = BINARY_DOUBLEOID; break;
            case DATEOID:         arg2 = ORADATEOID; break;
            case TIMESTAMPOID:    arg2 = ORATIMESTAMPOID; break;
            case TIMESTAMPTZOID:  arg2 = ORATIMESTAMPTZOID; break;
            default: /* do nothing */;
        }
    }
    // 5. arg1 是 PG, arg2 是 Oracle → 把 PG 转 Oracle
    else if (arg2_is_oracle) {
        switch(arg1) {
            case BPCHAROID:       arg1 = ORACHARCHAROID; break;
            case VARCHAROID:      arg1 = ORAVARCHARCHAROID; break;  // ← 这里!
            case NUMERICOID: ...  arg1 = NUMBEROID; break;
            // ... 同上 ...
        }
    }
    // 6. 双方都是 PG → 不转换
    else {
        PG_RETURN_BOOL(false);
    }
    // ... 后续选 precedence ...
}
```

## 4. Oracle 类型优先级表

`compatible_oracle_precedence.c:39`:

```c
#define ORACLE_DATATYPE_MEMBER 15

static const int OracleDataTypePriority[ORACLE_DATATYPE_MEMBER][2] = {
    {ORACHARCHAROID,       1},  // Oracle CHAR
    {ORACHARBYTEOID,       1},
    {ORAVARCHARCHAROID,    2},  // Oracle VARCHAR2
    {ORAVARCHARBYTEOID,    2},
    {NUMBEROID,            3},  // Oracle NUMBER
    {BINARY_FLOATOID,      4},
    {BINARY_DOUBLEOID,     5},
    {ORADATEOID,           6},  // Oracle DATE
    {ORATIMESTAMPOID,      6},
    {ORATIMESTAMPTZOID,    6},
    {ORATIMESTAMPLTZOID,   6},
    {YMINTERVALOID,        6},
    {DSINTERVALOID,        6},
    {InvalidOid, 0},
    {InvalidOid, 0},
};
```

数字越大优先级越高。算子结果类型 = 优先级高的那个。

## 5. 完整案例 — `'a'::varchar2 || 'b'::varchar`

### SQL 输入

```sql
SELECT 'a'::varchar2 || 'b'::varchar;
```

### 步骤 1:解析

Oracle parser(`ora_raw_parser`)识别 `'a'::varchar2` 和 `'b'::varchar`:
- `varchar2` → `ORAVARCHARCHAROID` (新建的 OID)
- `varchar` → `VARCHAROID` (PG 原生)

解析产物:`RawStmt` 里两个 `A_Const`(字面量)+一个 `AEXPR`(|| 算子)

### 步骤 2:运算符解析

`pg_parse_query` → `transformStmt` → 处理 `AEXPR` → 调 `oper(opname='||', ltypeId=VARCHAROID, rtypeId=VARCHAROID)`

### 步骤 3:`binary_oper_exact` 第一次查找

```c
OpernameGetOprid('||', VARCHAROID, VARCHAROID);  // 找到 PG 原生 || 算子
// → 返回 OID,直接用
```

**等等,这一步其实直接找到了** — PG 有 `(varchar, varchar) → text` 的 || 算子。

**但如果 PG 没有这个算子**:
- 比如 `'a'::VARCHAR2(100) || 'b'::VARCHAR2(200)` 两个都是 ORAVARCHARCHAROID:
- `OpernameGetOprid('||', ORAVARCHARCHAROID, ORAVARCHARCHAROID)` 找不到
- 触发 hook

### 步骤 4:hook 改写类型

两个都是 Oracle 类型 → 进 precedence 选择:
- `get_precedence(ORAVARCHARCHAROID) = 2`
- `get_precedence(ORAVARCHARCHAROID) = 2`
- 相等 → 都用 ORAVARCHARCHAROID
- 重试 `OpernameGetOprid('||', ORAVARCHARCHAROID, ORAVARCHARCHAROID)`
- 找到 Oracle 的 VARCHAR2 || VARCHAR2 算子(由 ivorysql_ora 注入)

### 步骤 5:PG 原生执行器跑

执行器看到的算子是 `ORAVARCHARCHAROID || ORAVARCHARCHAROID`,这是 PG 已注册的 C 函数(由 Oracle 兼容插件提供)。执行器和底层都是 PG,完全无需感知"Oracle"。

## 6. 另一种情况 — `'a'::varchar2 || 'b'::bpchar`

| 操作 | 类型 |
|------|------|
| `'a'::varchar2` | `ORAVARCHARCHAROID` |
| `'b'::bpchar` | `BPCHAROID` |

### 流程

`binary_oper_exact` 找不到 `(ORAVARCHARCHAROID, BPCHAROID) ||` 算子 → 触发 hook

`pg_compatible_oracle_precedence(ORAVARCHARCHAROID, BPCHAROID, '||', ...)`:
- `arg1` 是 Oracle
- `arg2 = BPCHAROID` 进 switch → 改写为 `ORACHARCHAROID`
- 返回 `(ORAVARCHARCHAROID, ORACHARCHAROID)`

两个都是 Oracle 类型 → precedence 都是 2 → 用 Oracle 算子。

## 7. 关键认知 — "类型转换"≠ 数据转换

**重要事实**:
- `VARCHAR2` 字段存的数据和 `VARCHAR` 字段存的数据**完全相同**(都是 UTF-8 字符串)
- "转换"只发生在**运算符解析时**(为了找对应的 C 函数实现)
- 数据本身在存储 / 计算时**不需要做任何额外转换**
- 这是 **OID 层面的转换**,不是**数据层面的转换**

## 8. 这个设计的优雅之处

- ✅ **PG 原生类型系统零改动** — `varchar`、`text`、`int4` 都在原位
- ✅ **Oracle 类型以新 OID 形式并存** — 在 pg_type 表里有独立条目
- ✅ **算子解析时按 hook 规则统一协调** — 不用改 PG 核心
- ✅ **升级 PG 主分支时零冲突** — 只是新增 OID,不动内核

## 9. 如果你想自己验证

```bash
# 在 IvorySQL Oracle 模式下
SET ivorysql.compatible_mode = 'oracle';

-- 看看 pg_type 里有什么
SELECT typname, oid::regtype
FROM pg_type
WHERE typname IN ('varchar', 'varchar2', 'char', 'bpchar',
                  'numeric', 'number', 'int4', 'float4',
                  'date', 'timestamp', 'timestamptz')
ORDER BY typname;

-- 应该看到:
--   bpchar     (PG CHAR)
--   char       (Oracle CHAR,ORACHAR)
--   date       (PG)
--   float4     (PG float4)
--   float8     (PG float8)
--   int4       (PG int4)
--   numeric    (PG numeric)
--   number     (Oracle NUMBER)
--   timestamp  (PG)
--   timestamptz(PG)
--   varchar    (PG varchar)
--   varchar2   (Oracle VARCHAR2)

-- 然后看 || 算子
SELECT oprname, oprleft::regtype, oprright::regtype, oprresult::regtype
FROM pg_operator
WHERE oprname = '||'
  AND (oprleft = 'varchar'::regtype OR oprleft = 'varchar2'::regtype);
```

## 10. 一句话总结

**VARCHAR2 和 VARCHAR 在 IvorySQL 里是 pg_type 表里的两个独立 OID 类型。**
**"VARCHAR2 变 VARCHAR"的说法不准确 — 实际是:**
- **数据存储层**: **两者完全相同**(都是变长字符串)
- **运算符解析层**: **hook 把 PG 类型 OID 改写成 Oracle 类型 OID**,**只为找对应算子实现**
- **执行层**: **Oracle 算子调用 PG 原生 C 函数**(数据类型系统不变)

这就是 " **解析层分离,执行层统一** " 在数据类型层面的具体体现。
